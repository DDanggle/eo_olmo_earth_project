# 재난 물리 모델에서 OlmoEarth–VLM으로 가져올 수 있는 것

2026-09-27. 독립 문헌 조사와 미실행 실험 제안. 외부 1차 자료는 아래 여섯 개로 제한했다. [현재 연구 계획](/Users/dongdong/DongDong/ai_projects/eo_olmo_earth_project/docs/OLMOEARTH_VLM_ARCHITECTURE_DATA_PLAN_20260927.md)의 PASTIS 준비 순서를 유지한다. 데이터·모델 다운로드, GPU 실행, 연구 저장소 수정은 수행하지 않았다.

가장 작은 후보는 **PROSAIL로 계산한 분광 적합도와 역문제의 모호성이 교정 예시의 전이를 예측하는지 검사하는 것**이다. 홍수 수리 모델은 별도 유역 입력이 필요한 후속 후보다. 물리 모듈을 붙이는 것, 합성 자료를 늘리는 것, VLM이 물리 용어를 말하는 것만으로 새 방법이나 실제 관측 성능을 주장할 수 없다.

## 관측 연산자를 생략하면 안 되는 이유

다음 식은 자료를 연결하기 위한 설계 개념도이며, 현재 코드에 구현한 모델이 아니다.

```text
홍수:
DEM + 강우/경계 유량 + 조도 + 초기·경계 조건
    -> 수리 모델 -> 수심 h(x,t), 유속 -> 침수 범위 1[h > 임계값]
    -> 별도 SAR 관측 연산자 -> VV/VH 후방산란 -> 실제 제품 전처리

식생:
잎·수관 파라미터 θ + 토양 + 태양/관측 기하
    -> PROSAIL -> 파장별 수관 반사도 ρ(λ)
    -> 센서 SRF 적분 -> 밴드별 반사도
    -> 실제 제품과의 차이·잡음·유효성 처리 -> OlmoEarth 입력 정규화
```

홍수에서 수면 고도와 수심은 다르며 수심은 지면 높이를 뺀 값이다. 물의 보존 법칙은 수리 상태에 적용한다. SAR 밝기나 임의 EO embedding이 보존된다고 강제하는 근거는 없다. SAR 관측에는 수면 거칠기, 식생·건물 산란, 입사각·편파와 speckle 등의 효과가 들어간다. 따라서 **침수 범위 mask를 SAR 영상으로 취급하거나, 물리적으로 그럴듯한 mask를 실제 전문가 mask와 같은 정답으로 섞지 않는다.** 영구수역과 새 홍수도 한 시점의 수심만으로 구분되지 않는다. 이 해석은 [ANUGA의 역할](https://github.com/anuga-community/anuga_core)과 [실제 침수 식생 관측](https://www.mdpi.com/2072-4292/10/8/1286)을 연결한 추론이다.

광학 경로는 상대적으로 가깝다. 센서 밴드의 예측값은 `∫ρ(λ) SRF_b(λ)dλ / ∫SRF_b(λ)dλ`로 구성할 수 있다. 그래도 대기 보정 잔차, 관측 기하, 혼합 화소·공간 해상도, 구름과 센서 잡음이 남는다. PROSAIL은 작물 종류·피해 원인·생장 시계열의 생성 모델이 아니다. 서로 다른 물리 파라미터가 비슷한 분광을 만들 수 있으므로 작은 재구성 오차가 실제 파라미터의 정확성을 보장하지 않는다. PROSAIL/SRF 역산 절차는 [공식 문서](https://jbferet.gitlab.io/prosail/articles/prosail-hybrid_inversion.html), 물리 decoder를 이용한 기존 학습은 [PROSAIL-VAE 저자 설명](https://www.cesbio.cnrs.fr/multitemp/biophysical-parameter-retrieval-from-sentinel-2-images-using-physics-driven-deep-learning-for-prosail-inversion/)에 근거한다.

## 옮길 메커니즘: 물리적 진단값이 교정의 적용 정도를 예측하는가

제안은 “가뭄이면 이 밴드가 내려간다” 같은 단일 규칙을 VLM에 암기시키는 것이 아니다. 같은 ROI·날짜의 관측에서 계산한 **분광 적합 오차, 여러 가능한 물리 상태의 퍼짐, 관측 기하 민감도**가 다른 지역 support의 도움/피해를 예측하는지 검사한다. 값마다 원 ROI·날짜·입력 밴드·시뮬레이터 버전·가정을 함께 기록한다. 현재 bandset=1인 OlmoEarth 출력 token을 개별 파장 token으로 해석하지 않는다.

처음에는 물리 변수 회귀와 새 VLM 학습을 동시에 추가하지 않는다. 원 격자 특징과 일반 교정 reader를 고정한 뒤 작은 gate의 입력만 바꾸어 원인을 분리한다. 물리 진단은 원 반사도에서 계산하고 VLM에는 실제 선택 영역과 연결된 도구 결과로 전달한다. 같은 결과를 전문 분할기→같은 Qwen 경로에도 제공해야 VLM 결합의 추가 가치를 가를 수 있다. 추가 역산 시간·튜닝·후보 라벨 비용도 계산한다.

## 반증 실험 1 — PROSAIL 진단은 일반 분광 거리보다 교정 전이를 잘 예측하는가

**가설.** support와 query의 물리 적합도 차이를 함께 쓰면, 같은 수의 양성·혼동 필지 교정을 받는 일반 gate보다 새로운 개발 지역에서 혼동 오탐을 줄인다. 여기서 평가 정답은 PASTIS 작물 mask다. LAI나 식생 건강의 정확도를 주장하지 않는다.

**가장 작은 준비 산출물.** 상위 작업의 PASTIS 실제 2사례 준비가 통과하면, CPU에서 최대 4,096개 PROSAIL 분광으로 작은 LUT를 만든다. 이 개수는 비용을 제한하기 위한 제안값이며 정확도·시간을 측정한 값이 아니다. 실제 존재하는 밴드만 맞추고, 각 사례의 구름 없는 필지 내부에서 최대 32개 위치×최대 2개 실제 날짜를 읽는다. 각 관측에 가까운 LUT 해와 오차, 상위 후보 파라미터 범위, 기하 가정을 기록한다. 파라미터 범위는 **LUT 후보의 모호성**이며 보정된 posterior나 신뢰구간이라고 부르지 않는다.

원자료가 준비된 뒤의 제안 파일은 `prosail_lut_contract.json`, `prosail_two_case_diagnostics.csv`, `prosail_two_case_diagnostics.md` 세 개다. 두 사례는 입출력과 수치 범위 확인용이다. 이를 일반화 성능 실험으로 세지 않는다. 한 밴드를 제외하고 맞춘 뒤 그 밴드를 예측하는 검사는 자기일관성 진단으로만 사용한다.

**실제 비교 단계.** 여러 parent tile의 개발 관측을 확보한 후 같은 dense branch·EO 특징·public mask·support 수·gate 용량으로 아래를 비교한다.

| 군 | gate가 받는 추가 정보 | 통제하려는 설명 |
|---|---|---|
| B0 | 일반 EO support–query 유사도 | 기본 교정 reader |
| B1 | B0 + 원 분광 거리/공분산 기반 거리와 유효 관측률 | 원 스펙트럼과 품질 정보가 추가되어 좋아진 것인지 |
| B2 | B0 + 동일 차원의 일반 스펙트럼 재구성 오차 | 물리 제약 없는 작은 재구성 모델로도 설명되는지 |
| P | B0 + PROSAIL 적합 오차·LUT 후보 퍼짐·support–query 진단 차이 | 물리 가정이 추가로 도움이 되는지 |

모든 군에 동일한 원 반사도 접근·관측 기하·품질 정보를 허용한다. B2를 학습하거나 LUT 범위·gate를 선택하는 자료는 학습 fold에 한정한다. 같은 utility 감독을 사용하며 지역·연도·parent tile 단위로 cross-fit한다. query gold로 support를 고르거나 역산 prior를 튜닝하지 않는다. 단순 LUT/SVR 물리 요약→공통 판독기→같은 Qwen도 추가 도구 기준선으로 둔다. 이 기준선이 동등하면 VLM 내부 물리 학습의 기여를 주장하지 않는다.

**판정.** 실제 작물 foreground IoU, 확인된 혼동 클래스 오탐, 동일 품질에 필요한 독립 support 수를 지역별 paired 비교한다. 같은 mask·측정값을 준 Qwen 결과를 별도로 보아 언어 경로의 이득을 분리한다. P가 B1/B2보다 낫지 않거나, 이득이 같은 지역에만 남거나, 진단값을 섞어도 유지되면 물리 기반 교정 전이 가설을 기각/축소한다. LUT 적합 오차 감소 자체는 성공 기준이 아니다. 작은 시뮬레이션 perturbation 테스트는 부차적 진단이다.

**착수 전제.** 원 PASTIS 반사도 스케일과 normalization 역변환, 10→12 채널 결측 mask, 실제 날짜·유효 위치가 확인되어야 한다. 없는 밴드를 0 반사도로 역산하지 않는다. 원 취득의 관측 기하가 없으면 metadata 확보 또는 명시한 기하 범위에 대한 주변화/민감도 검사가 필요하다. 고정 가상 각도를 실제 관측값으로 기록하지 않는다. simulator 설치 여부·해당 raw 파일·geometry 확보는 이 조사에서 검증하지 않았으므로 준비 완료로 표시하지 않는다. 실제 생리 변수 주장을 추가하려면 별도 현장 측정이 필요하다.

## 반증 실험 2 — 수리 ensemble 공간 prior가 지형 대조보다 SAR 교정에 도움이 되는가

**가설.** 알려진 유역에서 불확실성을 포함한 수리 ensemble의 침수 가능 범위가, 같은 DEM·강우/유량 정보를 받은 일반 gate보다 홍수/영구수역 혼동을 줄인다. 침수 mask를 합성 SAR로 바꾸어 EO encoder를 학습하는 실험은 아니다.

**먼저 할 수 있는 값싼 부분.** ANUGA의 작은 예제 유역에서 2–5천 정도 삼각형과 16개 이내 조건을 제안 한도로 두고 유입·조도를 바꿔 ensemble 범위를 계산한다. 깊이 음수·mass balance·입력 단위·시간축·영구수역 처리 등을 확인한다. 크기·시간은 아직 벤치마크하지 않았으며 설치/실행은 이번에 하지 않았다. 이 합성 진단으로는 실제 홍수 탐지의 효과를 평가할 수 없다.

**실제 비교 단계의 전제.** Kuro 사건 하나를 고르기 전에 유역 범위 DEM, 취득 시각과 맞는 강우/유입·초기·경계 조건, 조도 범위, 공간 정합을 확보해야 한다. 잘린 영상 패치의 경계를 임의 폐쇄하고 실제 유역 해석으로 부르지 않는다. 공개 Kuro 카드만으로 이 전제가 충족되지는 않는다. 우선 수리 prior를 넓은 확률 범위로 사용하고 관측상 홍수를 강제로 삭제하는 hard mask로 쓰지 않는다.

| 군 | 같은 SAR·support 위에 추가하는 정보 |
|---|---|
| F0 | SAR 전후 변화 + DEM/경사·배수 연결성 기반 단순 지형 prior |
| F1 | F0에 사용한 모든 원 입력과 실제 확보한 강우/유량을 받는 일반 learned gate |
| FP | 같은 원 입력 + 수리 ensemble 범위를 사용하는 동일 용량 gate |

실제 공개 전문가 mask와 valid mask로 홍수 IoU·영구수역 혼동을 사건별 비교한다. 기존에 확인한 Kuro test 사건은 개발 자료이며 새 봉인 평가가 아니다. 수리 prior 생성에 평가 mask를 사용하지 않는다. 원격 관측이 있는 취득 시점 판독과 관측 전 미래 예측도 구분한다. 새로운 사건에서 FP의 이득이 단순 지형/입력 추가로 설명되거나, 침수 식생·도시에서 과도하게 false negative를 만들거나, 위치를 섞은 prior와 비슷하면 수리 메커니즘의 이점을 기각한다. 실제 수심 정답이 없으므로 수심 정확도·재난 예보 성능은 이 실험의 결론이 아니다.

## 현재 작업과 연결할 단 하나의 다음 항목

PASTIS 실제 공개 mask가 붙은 2사례의 native 입력 계약을 먼저 완료한다. 그 후에도 본 모델 비교를 지연시키지 않는 별도 CPU 진단으로 **“같은 두 사례의 원 반사도를 PROSAIL LUT와 비교할 수 있는가”**만 확인한다. 유효 반사도·관측 기하가 없으면 누락 필드를 기록하고 종료한다. 즉시 확장 가능한 것은 입력 계약과 진단 산출물이며, 물리 감독 데이터가 새로 확보된 것이 아니다. 홍수 수리 실험은 유역 강제력과 경계 입력이 확보될 때까지 후순위다.

이번 조사에서 작성한 것은 본 제안 문서뿐이다. 시뮬레이터 설치, LUT 생성, 파라미터 역산, 실제 평가, 추가 학습은 모두 미실행이다.
