# OE7 통합 초안 최종 통계 검토

2026-09-27. 대상: `OLMOEARTH_NEXT_EXPERIMENT_DESIGN_20260927.md`. 초안 직접 수정 없음.

**정합 확인:** K=0을 named-target의 별도 조건으로 둔 것과, 주 AUC를 K={1,2,4,8}에서 선형 사다리꼴 합/7로 정의한 것은 서로 모순되지 않는다. source-support 전이와 target-support 적응의 개념 구분, dev 부모1개에서 유의확률을 제시하지 않는 제한도 적절하다. 아래4개만 보강하면 된다.

1. **[필수: 비용] test120의 이중 검수와 K별 교정 제작을 예산에서 명시적으로 분리.** §10은 episode와 교정 쌍의 단위 차이를 밝혔지만, 현재60인시가 query 정답 검수와 support 제작을 모두 감당한다는 인상을 완전히 막지는 못한다. 기존 test120×2인×8분=32인시는 query 판독/검수 몫이다. K=8 교정 제작·검색·재작업을 별도로 추가하거나 이를32인시 안에 포함해 time pilot으로 가능한 query 수를 줄여야 한다. 권장 문구: “120개 test 이중 검수는 교정8쌍×120개 제작 예산을 포함한다는 뜻이 아니다. support library 제작·검수와 query gold 검수의 시간을 따로 적산하고, 총60+4인시 안에서 사례 수를 확정한다. 부족하면 비용을 늘리지 않고 목표 수량·통계 충분성을 수정한다.”

2. **[필수: 비용 주장] ‘timed replay’가 무엇을 측정하는지 명시.** §10 마지막의 “실제 인간 시간 절감 … timed replay”는 저장된 교정을 컴퓨터가 재생하는 시간과 사람의 작업 시간을 혼동할 수 있다. 고정 support replay는 모델 비교이고, 사람 비용 비교는 실제 기록한 검색·판독·표시·확인·수정 person-minutes를 해당 support prefix에 연결한 비용–품질 곡선이다. 이것은 방법마다 사람과 상호작용하며 걸리는 시간 단축의 직접 증거와도 구분해야 한다. UI/순서가 다른 사용자 실험의 시간 절감을 주장하려면 별도 균형 배치 pilot이 필요하다. 권장: “고정 교정 재생 성능에 실제 support 작성·검수 person-minutes를 연결한다. 방법별 상호작용 시간 절감은 별도 사용자 비교 전에는 주장하지 않는다.”

3. **[필수: K 비교] AUC의 query 집합·집계 가중치를 K와 방법 사이에서 고정.** §8은 K=8 부족 시 전체 지표를 미산출로 남기는 좋은 제한이 있으나, K별로 해당 작물·query가 있는 subset만 남기면 난도가 달라져 곡선이 왜곡될 수 있다. 권장: “각 source/target-support 조건별로 모든 K를 평가할 공통 query·class_pair·support draw 집합을 모델 결과 전 고정한다. 지역 내 대상별 macro 후 지역별 macro 등 집계 순서·가중치를 명시하고 모든 K/방법에 공유한다. 부족한 K에 맞춰 query를 사후 교체하지 않는다.” target-present/absent 분리도 같은 고정 query 명세로 유지한다. 현재 AUC 공식 자체는 수정할 필요가 없다.

4. **[중요: 교정 전이 해석] source support의 영역 정답이 episode 학습에 이미 사용됐는지 분리.** §4의 “학습 지역에서 만든 동일 support”는 지역만 지정한다. 평가 support가 학습에서 반복 등장한 동일 객체·정답이면, K곡선은 새 교정 이용보다 기억한 training exemplar 재제공을 측정할 수 있다. 권장 기본안: 학습 지역 내에서도 평가 support용 필지/객체 bank를 episode 학습의 support/query와 분리하고, 원영상·정답의 노출 내역을 기록한다. 기존 학습 exemplar 재사용 조건도 유용하지만 별도 이름으로 보고하고 새 교정 전이와 합치지 않는다. region-disjoint인 query 조건은 그대로 유지한다. 이 bank의 제작/검수 비용도 총 library 비용에 포함한다.

**추가 모순 없음:** 현재 초안은 표본 수·효과폭·power를 확정했다고 하지 않으며, 개발 go/no-go를 확증 성공과 구분한다. 최소 실용 효과는 실제 사용 가치에서 정하고, 분산/표본 수는 그 효과를 검출할 수 있는지 판단하는 데 써야 한다. 표본이 적다는 이유로 의미 있는 효과의 정의 자체를 맞추지 않는 원칙만 최종 분석계획에서 유지하면 된다.
