# OE7 실험설계 독립 검토: 통계·누출·교정 비용

2026-09-27. 현재 설계에 대한 검토이며 확증 사전등록·power 분석·새 실행 결과가 아니다. 검토 자료: `docs/OLMOEARTH_CROSSDOMAIN_LOOP_PLAN_20260927.md`, `docs/OE6_PASTIS_INPUT_PROGRESS_20260927.md`, v4 아키텍처 계획, `config/eo_vlm_labeling_budget_v2_20260926.json`. 현재 준비 완료는 공학 입력 2개, 다음 단계는 학습64/개발16개의 메타데이터 후보다. 비교 GPU 학습은 미시작이다.

## 1. 먼저 두 주장을 분리한다

1. **모델의 교정 이용 능력:** 같은 support와 query를 받은 일반 모델보다 제안 모델이 잘 판독하는가? 모든 군에 동일한 고정 교정 기록을 재생한다. 교정 선택 효과를 섞지 않는다.
2. **교정/관측 선택 정책:** 같은 전체 후보 접근권·사람 시간·관측 읽기 비용에서 더 유용한 정보를 고르는가? 선택 결과가 달라지는 별도 정책 비교다. 기존 공개 정답으로 수행하면 모의 교정 선택 실험이고, 실제 사람 비용은 별도 측정한다.

둘의 이득을 확인한 뒤 통합 모델을 평가한다. 제안군만 더 적합한 support 또는 추가 관측을 받는 비교로 모델 구조의 효과를 주장하지 않는다. 선택 loop의 최종 관측 집합을 단발 reader에도 제공하는 대조를 유지한다.

## 2. support/query 및 개발/확증 분리

- **분할의 최상위 단위:** PASTIS는 부모 지역과 연도, Kuro는 홍수 사건. 같은 원 장면에서 파생한 crop·질문·복수 날짜·증강은 같은 split에 묶는다. 동일 원영상의 중첩 crop을 독립 사례로 세지 않는다. PASTIS 단일 연도 결과로 미래 연도 전이를 주장하지 않는다.
- **객체 분리:** support와 query의 원 필지/객체 ID 및 footprint가 겹치지 않아야 한다. 인접 patch라도 필지가 경계를 넘을 수 있으므로 patch ID 차이만으로 통과시키지 않는다. 현재 정확한 footprint/원 필지 ID가 완전하지 않으면 확인 가능한 parent 단위 분리를 우선하고, 그보다 세밀한 독립성은 미확인으로 기록한다. 공간 buffer는 자료 해상도·객체 크기에 맞춰 개발에서 정한 후 고정한다.
- **원천 지역 교정 전이:** support는 원천 지역, query는 미관찰 대상 지역에서 가져온다. 대상 지역의 라벨을 support 선택·튜닝에 사용하지 않는다. 이것이 현재 핵심 주장과 가장 직접적이다.
- **대상 지역 few-shot 적응:** 대상 지역의 별도 support 필지에서 K개 교정을 받아 나머지 query에 적용한다. 이는 대상 지역 라벨 사용을 허용하는 별도 설정이다. 무라벨 지역 전이와 한 표의 같은 조건으로 취급하지 않는다.
- **query 정답은 scorer만 접근:** query mask로 가장 틀린 위치를 골라 교정을 주면 그 query의 interactive segmentation 실험이 된다. 이를 별도 query로의 교정 전이라고 부르지 않는다. 평가 selector는 실제 관측·질문·이전에 받은 support만 본다. offline oracle은 상한 참고로만 표시한다.
- **학습 utility의 cross-fitting:** utility 목표 생성 모델과 support/query는 지역/연도/원영상 단위로 분리한다. 같은 crop에서 만든 다른 질문을 fold 분리로 세지 않는다. utility용 공개 정답 library와 계산량을 전체 감독·비용 장부에 포함한다.
- **표현 학습 노출:** native replay·추가 사전학습에도 확증 query 및 인접 장면을 넣지 않는 경로를 기본으로 한다. 불가피한 미라벨 노출은 transductive 설정으로 별도 표기한다. 원 OlmoEarth 사전학습의 노출을 완전히 감사하지 못하면 '학습에서 한 번도 보지 않은 지역'이라고 단정하지 않는다.
- **기존 노출 자료:** 과거 Kuro test 관찰 사건은 개발용이다. PASTIS 예비 부모 지역도 과거 노출 감사 전에는 봉인 test로 승격하지 않는다. 이번 육안 날짜 선택 2사례는 공학 검사이며 확증 사례에 넣지 않는다.

평가 manifest는 `source_version/hash, parent/event, parcel/footprint 확인 상태, dates, class_pair, support_ids, query_ids, question_template, exposure, split_reason`을 기록한다. split별 집합 교차 및 원영상 중복 검사를 학습 전에 실행한다.

## 3. 공개 mask 교정과 실제 사람 교정

### 공개 mask를 이용한 모의 교정

공개 작물/홍수 mask에서 support의 대상 영역과 혼동 영역을 추출한다. 질문은 그 라벨이 실제로 보장하는 내용만 만든다. PASTIS 연간 작물 정답으로 건강·고사·변화일을 만들지 않는다. Kuro mask를 전문가가 실제 대화에서 남긴 교정 기록으로 표현하지 않는다.

이 설정은 많은 교정 조건에서 모델의 이용 능력을 비교하는 데 유용하다. 다만 정답에서 바로 이상적인 영역을 얻으므로 사람의 찾기·판독·검증·불확실성 비용을 제거한다. 결과의 명칭은 `mask-derived synthetic corrections` 또는 '공개 정답으로 구성한 모의 교정'으로 고정한다. 교정 수 곡선을 곧바로 사람 시간 절감으로 환산하지 않는다.

### 사람 교정

기존20개 시간 측정 pilot에서 지침 이해, 영상/후보 검색, 대상 표시, 혼동 영역 표시, 수정, 확신 부족/관측 불가, 검수 시간을 각각 기록한다. 유효 교정의 정의와 UI를 고정한다. 사람은 평가 모델명/가설을 모르게 하고, 방법별 사용자 실험이 필요하면 작업 순서·사례 순서를 균형 배치한다. 동일 사람이 같은 query를 여러 모델에서 반복해 답을 외우는 설계를 피한다.

공통 교정 library를 재생하는 모델 비교는 사용자 실험보다 작게 시작할 수 있다. 다만 이것만으로 모델별 실제 상호작용 시간 감소를 입증했다고 쓰지 않는다. AI는 초안·후보 선택에 쓰되 AI 합의율을 gold로 쓰지 않는다. 사람이 생성한 support와 query 정답 검수는 역할·ID로 구분하고, 평가 정답이 support로 유입되지 않도록 한다.

## 4. 0/1/2/4/8 budget과 분모

이번 요청의 K={0,1,2,4,8}은 v4의 K={1,5,20}과 다른 **새 개발안**이다. 결과를 본 뒤 유리한 budget만 보고하지 않고, 확증 전 한 집합으로 동결한다.

**권장 단위:** `1 correction = 독립 support 사례 1개의 대상 영역 + 확인된 혼동 영역 + 관측/정의`라는 하나의 교정 묶음. 영역 두 개를 한 묶음으로 세는 사실을 공개하고 영역 수/클릭 수/시간도 같이 저장한다. 클릭 한 번이나 질문 한 개와 같은 단위로 혼용하지 않는다. 한 필지의 여러 증강은 새 독립 교정이 아니다. 묶음 작성이 과도하면 pilot에서 단위를 바꾸고 본 실험 전에 명시적으로 버전을 올린다.

- 고정 교정 비교는 미리 생성한 8개 순서의 prefix로 K=1/2/4/8을 만든다. 같은 support draw·순서를 모든 방법과 training seed에 공유해 paired 비교한다. 오류가 난 사례를 사후 삭제하거나 성능이 좋은 순서만 고르지 않는다.
- K=0에서도 대상 정의 텍스트/동일한 task specification을 제공한다. support가 필수인 prototype 모델의 K=0은 미정의로 표기하며 0점으로 넣지 않는다. 공통 무교정 reader를 사용할 경우 구성 변경을 표시한다. 모의 비교의 공통 AUC 대상은 실제 모든 K에서 정의된 모델들이다.
- 교정 선택 정책 비교에서는 prefix가 방법마다 달라질 수 있다. 동일한 최대 후보 library와 정답 요청 횟수, 후보 확인 비용, 전체 관측 예산을 제공한다. 전체 라벨 library를 사전에 읽고 최적 8개를 선택했다면 비용은 8개가 아니라 library 작성/검수까지 포함한다.

**권장 개발 주지표:** 부모 지역별 class-balanced foreground IoU로 만든 raw K 곡선과 normalized trapezoid AULC:

`AULC = (1/8) * Σ_i (K[i+1]-K[i]) * (Q[K[i+1]]+Q[K[i]])/2`.

여기서 `Q`는 동일한 고정 query 집합의 결과다. 각 사례의 class/void/empty-mask 처리와 지역 집계 순서를 고정한다. 혼동 대상 false-positive rate와 근거가 맞는 답변 비율은 별도 보조/guardrail로 보고한다. K가 늘었을 때 하락한 점도 그대로 남긴다. 원 curve와 AULC를 함께 보고, log-K 축 AUC로 사후 교체하지 않는다.

**사람 비용 주장의 분모는 별도:** 아래 두 비용을 구분한다.

1. 서비스 사용 시 marginal 비용: 신규 support 찾기+판독+표시+검증+수정의 person-minutes. 단지 제출 버튼까지의 UI 시간으로 줄이지 않는다.
2. 총 프로젝트 감독 비용: 기존 library 제작/검수·지침·전문가 교정·train/dev/test 정답 제작 비용. 재사용 N건으로 나눌 경우 N과 amortization 가정을 명시한다. GPU/API 비용은 사람 시간과 별도 축이다.

같은 품질에 필요한 비용을 주장하려면 개발에서 정하고 test 전에 동결한 품질 목표 τ와 혼동 오탐 제한을 사용한다. 각 실제 측정 budget에서의 비용·품질을 함께 보고한다. 어느 방법이 τ에 도달하지 못하면 `>8 corrections` 또는 `>측정시간 상한`으로 표시하며 외삽으로 배수 절감을 만들지 않는다. 시간 budget의 관측이 부족하면 고정 시간의 품질 비교만 주장한다. 작은 모의 AULC 상승으로 사람 비용 절감의 크기를 추정하지 않는다.

## 5. 통계: 지역 수가 표본 수다

현재64train/16dev는 원 입력 준비 전이며 dev 부모는1개다. 이 상태로 지역 일반화의 CI·power·통계적 유의를 계산할 수 없다. 같은 지역의16개 query, 수천 필지, 여러 seed를 독립 지역 표본처럼 세지 않는다.

확증 단계에서는 각 방법의 동일 query/support draw/seed 결과를 먼저 원 사건·부모 지역 단위로 집계하고, 지역 단위의 paired 효과를 주 분석으로 한다. 충분한 독립 지역을 확보한 뒤 사전 지정한 cluster bootstrap 등으로95% CI를 구한다. bootstrap 시 같은 지역에 속한 모든 K·방법·반복 draw를 함께 재표집한다. training seed는 알고리즘의 변동을 보여주는 별도 반복 축이며 지역 수를 늘리지 않는다. geography-cluster CI가 조건부 seed 평균인지, seed 변동도 포함하는지 절차를 미리 명시한다.

독립 지역이 적으면 cluster bootstrap CI도 불안정하다. PASTIS의 소수 parent만으로 넓은 환경 일반화를 주장하지 않고, 지역별 paired 효과·support draw/seed 변동을 기술적으로 보고한다. 추가 지역/연도 또는 별도 데이터의 확보가 필요하다. 본래4개 parent를 seed처럼 돌려 최대 조합 수를 독립 지역 수로 세지 않는다.

**power는 현재 미정:** 사전에 과학적/운영적으로 의미 있는 최소 효과 δ를 정하고, 여러 개발 지역에서 얻은 지역별 paired 차이의 분산/상관과 예정 평가 지역 수로 설계를 평가한다. 테스트를 보고 δ나 제외 규칙을 맞추지 않는다. 대략적인 paired 정규 근사는 `N_regions ≈ [(z_alpha + z_power)*SD(region_delta)/δ]^2`이지만 지역 수가 적거나 불균형하면 이 근사값을 보증처럼 제시하지 않는다. 실제 분할 구조·방법 비교·censoring을 반영한 simulation/민감도 분석으로 확인한다. 120개 test episode가120개 독립 지역이라는 뜻은 아니다.

확증에서는 주 대조 한 개(최종 제안 vs 동결된 strongest matched baseline)·주지표 한 개를 먼저 정한다. 2×2 구조/학습 효과, 다른 reader/분야/지표는 별도 사전 지정 secondary 분석으로 두고, 다중 확증 주장에 맞는 보정을 정한다. 수많은 방법×K×class에서 가장 유리한 p-value를 주결과로 고르지 않는다. 신뢰구간이 넓으면 '미확정'이며 부재 입증이나 성공으로 바꾸지 않는다.

## 6. 공정성 계약

- 같은 원 관측과 class 정의, support/query, 지역 맥락, dense mask 감독, native replay, 실측/보완 밴드 상태를 제공한다. 제안군만 dense feature를 받는 비교를 피한다.
- pretrained checkpoint/revision, encoder trainable 범위, reader, 최대 입력·관측 읽기 예산을 고정한다. 같은 step 수만으로 계산비용이 같다고 주장하지 않는다.
- 일반 learned resampler·cross-attention·prototype·동일 utility 감독 일반 router를 충분히 학습한다. 모델별 합리적 optimizer 설정은 같은 검색 예산과 개발 자료 안에서 선택한다. 모두 같은 LR로 억지로 맞춰 한쪽이 덜 학습되지 않게 한다.
- full-grid는 비용이 다른 상한 참고다. 동등 token 수·관측 수·GPU시간의 비교를 각각 구분한다. utility label 생성, teacher call, library 검색, 실패 재시도 비용을 숨기지 않는다.
- 질문/지역 metadata만으로 맞히는 통제, support 교체, 관측 교체를 둔다. 교체 후 원 정답이 여전히 유효한지 감사한다. 효과 없는 불필요한 교정도 포함해 항상 교정을 따르는 모델을 보상하지 않는다.
- VLM 고유 가치는 강한 dense predictor+정확한 연산+동일 VLM과 비교한다. OlmoEarth 개선 주장은 같은 독립 EO readout protocol 및 다른 reader의 공정한 적응 예산으로 검증한다.

## 7. 개발 go/no-go와 확증을 분리한다

| 단계 | 다음 단계로 갈 조건 | 실패 시 해석/조치 |
|---|---|---|
| 입력 계약 | 80개 실제 변환, 고정 관측 품질 규칙, 날짜/밴드/label/void와 split 검사, 사용 불가 사례 장부 | 자료/전처리 문제를 수정. 이 단계 성공은 방법 성능이 아님 |
| 실행 계약 | 실제 trainer 저장복원(모델·optimizer·scheduler·RNG 등 필요한 상태), 로그/참조 결과 재현, 유한 loss·gradient, 작은 학습 fixture 적합 확인 | 실행 오류 수정. 작은 과적합은 일반화 근거가 아님 |
| 일반 기준선 | 충분한 개발 학습·튜닝, 단순/강한 기준선의 학습곡선과 비용 확인 | 약한 평균 pooling만 이기는 결과로 신규성 확대하지 않음 |
| 기전 pilot | 사전 고정된 개발 비교에서 주장한 실패가 재현되고 최소 구조/학습 변경의 효과가 support draw/seed에 지나치게 의존하지 않는지 확인 | 일반 resampler가 해결하면 구조 주장 축소. loop 최종 근거 단발 대조와 같으면 선택의 기여로 좁힘 |
| 확증 준비 | 여러 독립 평가 지역, 이전 노출 감사, 사람 pilot 시간, 비용·효과 목표·주 분석·중단/제외 규칙과 충분성 계획을 test 개봉 전 동결 | 자료/표본이 부족하면 탐색 결과로 보고하고 본 실험을 준비. 숫자를 늘렸다고 임의 승격하지 않음 |
| 확증 실행 | 잠근 manifest/config/checkpoint에서 한 번의 계획된 평가; 실패·제외·재실행 모두 기록 | 방법 변경은 개발 재개와 새 평가 자료/프로토콜을 필요로 함 |

기전 pilot의 작은 개발 차이는 확대 여부를 정하는 정보이지 확증 p-value가 아니다. 성공 기준의 수치(δ, 허용 EO 저하, latency 상한 등)는 지금 임의로 발명하지 않고 과제 가치·실측 비용·개발 분산을 보고, 평가 결과를 보기 전에 명시적으로 고정한다. 평가를 반복하다 유의해지면 멈추는 절차는 사용하지 않는다.

## 8. 예산은 기존100만원 그대로

검수72만원(총60인시), 전문검토16만원(4인시), API상한5만원, 예비7만원이라는 기존 가정을 바꾸지 않는다. 20pilot은 train200에 포함, dev60/test120독립2인검수는 시간 pilot 확인 전 목표다. API배정은 발주/호출 사실이 아니다.

특히 `test120 × K8 × 2인`의 새로운 교정 제작을 기존 test120두 사람 검수와 같은 업무량으로 취급하면 예산이 깨진다. 공통 support library 작성 시간과 query 정답 검수 시간을 별도 적산한 뒤 가능한 episode 수를 다시 산정해야 한다. 결과적으로 총 예산 안에서 사례 수가 줄면 이를 기록하고 power를 미확정으로 남긴다. 사람 교정 성능 입증이 약하면 공개 mask 기반 방법 결과와 소규모 사람 실현성 pilot을 명확히 구분한다.

## 검토 결론

지금 진행할 것은 80개 입력과 강한 일반 기준선의 개발 비교다. 주 연구축은 동일 정보에서 교정으로 지정한 구별을 다른 지역에 유지하는 학습이며, loop·tokenizer·cache를 전부 확증 요인으로 늘리지 않는다. 현재 지역 수와 사람 시간으로 본 실험이 충분하다고 선언할 수 없다. 먼저 교정 단위·실제 비용·누출 없는 split을 확인하고, 그 결과로 본 실험의 규모와 한 가지 주장을 동결하는 것이 맞다.
