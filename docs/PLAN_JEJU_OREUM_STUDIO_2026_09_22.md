## 2. 작업 패키지

### WP0 — 라벨 정의서 (Claude 초안 → 사용자 확정, 0.5일)
- 클래스: 기존 a/b/c/d **유지**(이미 UI에 있고, 임베딩 순위의 오탐 유형을 나누는 것이 1차 목적).
- a(실질 변화)에만 **세부 태그**를 붙인다 — 제주 등급제·IUCN 위협 항목에서 가져온 5개:
  `trail_erosion`(탐방로 침식·나지) · `veg_loss`(식생 손실: 병해·기후·산불) · `facility`(시설·도로·개간) ·
  `grazing`(방목·경작 변화) · `coastal`(해안 침식, 성산·송악 등) · `other`.
- 라벨 단위 = 오름 1곳(320 m 창) × 사건 쌍(2025→2026). 근거 = 전후 프레임 + VWorld 항공사진(이미 지도에 있음).
- 산출: `docs/LABEL_SPEC_OREUM_v1.md`(정의·예시 스크린샷 2장씩·판독 불가 규칙) + `apps/oreum-web/lib/labels.ts`에 태그 필드 추가.
- 게이트: 사용자가 정의서를 읽고 "이 정의로 찍겠다"고 확인. 이후 변경 금지(변경 시 v2로 새로).

### WP1 — 사람 라벨 60곳 (사용자, 3~4시간 / Claude: 도구 준비 1일)
- 대상: v8 상위 30(문도지·금오름·도너리·세미소·칡·누운·모구리·새신·본지·여절악·가마·밝은·정물·남산봉·마중·민오름×2·왕이메·당·설… ~30)
  + **대조 30**: 채점됐지만 깃발율 하위(< 중앙값 1.74%) 오름을 무작위 추출. 대조가 없으면 "상위=변화"가 순환논리.
- 도구: `apps/oreum-web` 라벨 UI를 60곳으로 확장(`LABEL_TOP_N` → 명단 파일), 태그 입력, **재판독 5곳** 무작위 재제시(자기 일치율).
- 내보내기: `labels.json` → (a) 저장소 커밋, (b) **Studio 스키마 변환**(`sample_category`=a/b/c/d, `sample_true_false`=a 여부, 폴리곤 320 m, 날짜 2026-08-15 사건 장면) → 4번째 데이터셋 `jeju_oreum_labels_v1` 임포트.
- 실패 보존: d(판독 불가) 사유를 자유 텍스트로 남긴다 — 이게 다음 라운드 데이터 요구사항(항공사진 연도, SAR)이 된다.

### WP2 — 결함 8 검증: 창별 예측 (Claude, 1 unit 이내, 1시간)
- `make_area_geojson.py`를 확장해 오름 15곳 각각의 **320 m 정사각 Area 15개** 생성 → Areas 업로드 → 제주 v2 모델 Run model(Area 다중 선택).
- 판정: 결과 GeoJSON feature 수. ≥15면 Studio 예측을 오름 단위로 쓸 수 있음(단 확률은 여전히 없음 → 결함 8은 "확률 부재"로 축소).
- 부산물: Ai2에 낼 버그 리포트 1건(재현 조건 확정).

### WP3 — Studio Embeddings API 시험 (Claude, 승인 필요, 예상 2~5 units)
- `/profile`에서 API 키 발급(사용자 클릭 1회; 키는 `.env`에만) → `olmoearth_projects/tutorials/embeddings/studio_client.py`로
  제주 오름 bbox(핵심 15곳 68 km² 먼저) · Tiny 192 · 40 m · 월별 2025-07~09, 2026-07~09 · S2 요청.
- 판정: (1) 비용이 100 units 안에서 243곳 전체(≈2,000 km²)를 감당하는지 실측, (2) 우리 v8 Δz(40 m 토큰 코사인)와
  Studio 임베딩 Δz의 **오름별 Spearman** — ≥0.6이면 "Studio만으로 1단계(변화 상위 10곳) 재현 가능".
- 실패 시(권한·비용): 문서화하고 Studio는 WP1의 라벨 공장으로만 쓴다. 이 결과 자체가 제품 발견.

### WP4 — 라벨로 재학습 (Claude, 2~4 units, WP1 뒤)
- Studio: `jeju_oreum_labels_v1` + 라벨 `sample_true_false`(a 여부) → Window 분류, "A condition"(2025-08-15 기준 전후 1개월; 과거라 결함 7 회피), Nano → Tiny 비교.
- 로컬 대조: 같은 60 라벨로 v8 캐시 임베딩 위 로지스틱 프로브(우리 방법). **같은 라벨·같은 분할**로 Studio 파인튜닝 vs 캐시 프로브 — EarthCache G0 질문의 제주판.
- 판정 기준은 §1. a가 10개 미만이면 학습 대신 "라벨 분포 보고"로 끝낸다.

### WP5 — 행정 기준선과의 대조 (Claude 조사 + 사용자 확인, 2일)
- 제주도 등급제 **등급별 오름 목록**(고시문·정보공개청구 필요 가능) + 휴식년제 5곳 + 개발행위허가 86건(이미 있음).
- 사전등록: "v8 상위 30 ∩ {휴식년제∪3등급}" 농축 검정(Fisher exact, 단측). 목록을 못 구하면 검정하지 않고 도너리 1건을 관찰로만 기록.
- 이 결과가 곧 제주도에 보낼 한 장(순위 지도 + "당신들의 등급과 이만큼 겹친다/안 겹친다").

### WP6 — 외부 데이터 연결 (Claude, WP1과 병렬, 2일)

## 5. 리스크
- **라벨러 1명**: 자기 재판독 일치율로 최소 방어. 두 번째 판독자(지인/제주 담당자)가 붙으면 Cohen κ로 격상.
- **2025 구름(65곳 관측불가)**: 라벨 대상은 채점 153곳에서만. 관측불가 90곳은 "라벨 불가"로 명시(분모 유지 규율).
- **Studio 변경**: 제품이 바뀌면 스크립트가 깨진다 — 실행 직전 DOM 프로브가 규칙.
- **개인정보·자격증명**: API 키는 `.env`만, 커밋 금지. 발행은 Restricted 유지.
