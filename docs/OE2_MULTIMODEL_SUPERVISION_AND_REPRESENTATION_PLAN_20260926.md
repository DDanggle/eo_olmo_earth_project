# OE2: 여러 AI의 감독으로 학습하고, 독립 판독으로 검증하는 OlmoEarth–VLM

> **후속 구체화: [TerraScope 대비·첫 VLM 실행 순서](OE2_TERRASCOPE_COMPARISON_AND_FIRST_VLM_20260926.md).** SPEX 등 더 가까운 선행과 서버 모델 재사용을 반영했다. 첫 실행은 Qwen3-VL-8B 연결 검사이며, 동일 연결부의 F/R/L/P 목적 비교를 먼저 둔다. 아래2×2와24/30회는 전체 연구 후보 계획이고 즉시 실행 queue가 아니다. 추가 대조를 포함한 최종 실행수는 별도 확정한다.

2026-09-26. **실행 전 연구 설계 v0. 동결 사전등록·완성된 구현·새 학습 결과가 아니다.** 사용자의 OpenRouter 다중 AI 제안을 반영했다. [앞선 규모 설계](EO_VLM_SCALE_AND_EXPERT_DATA_20260926.md)의 방법 비교는 유지하고, [100만 원 라벨링 계획](EO_VLM_LABELING_BUDGET_1MKRW_20260926.md)의 예비비 일부를 API 시험에 배정한다. OE1/E5/D1 결과와 원 사전등록은 변경하지 않는다.

## 1. 논문에서 답할 질문

**같은 위성 관측과 같은 정답으로 학습하더라도, 공간·수치 근거를 압축 뒤에 다시 읽도록 학습하면 OlmoEarth 표현이 실제 VLM에 더 유용해지는가? 그 효과가 연결부를 바꾸거나 새로운 지역에 적용해도 남는가?**

목표는 큰 EO–VLM을 만들고, 그 모델의 측정·근거 판독 능력이 왜 좋아졌는지 설명하는 것이다. 여러 AI는 감독 자료를 만드는 수단이다. API를 연결했다거나 AI들이 합의했다는 사실을 방법의 신규성으로 삼지 않는다.

현재 OE1의 blind 66.80 / frozen 68.36 / joint 72.27 BA는 작은 동일 과제의 단일 seed 결과다. plain Olmo3-7B와 16개 pooled token의 결합으로, 이 제안의 실제 pretrained VLM·공간 측정·새 reader 전이를 이미 시험한 결과가 아니다. [OE1 결과](OE1_BENTXT_FEASIBILITY_20260926.md)

가장 가까운 선행 중 [TerraScope](https://arxiv.org/html/2603.19039v1)는 기존 마스크·메타정보, Qwen3-VL, 자체 caption 모델, GPT-4o 등을 거쳐 큰 EO 합성 감독을 만들고 별도의 전문가 검증 평가를 보고한다. 이것은 다수결 실험과 같지는 않지만, **다중 모델 합성 감독·grounded caption·큰 데이터만으로 새로움을 주장하기 어렵다**는 직접적인 비교 대상이다. 우리 후보의 차별점은 OlmoEarth의 다중분광 표현에 대한 학습 개입과, 동일 감독 하 근거 회수·새 reader 전이를 함께 입증하는 데 있다. 아직 신규성이나 성능이 확정된 것은 아니다.

## 2. 논문 주장과 필요한 증거를 나눈다

| 질문 | 실험 | 결과가 지지하지 않을 때의 해석 |
|---|---|---|
| 여러 AI가 라벨을 더 잘 만드는가? | 강한 단일 teacher / 같은 계열 반복 검토 / 서로 다른 계열 검토의 비용–오류 비교 | 다중 AI를 버리고 더 싼 감독 경로 사용 가능. 표현 학습 가설과 별개 |
| 제안 학습이 일반 결합보다 좋은가? | 같은 확정 corpus를 쓰는 2×2 방법 비교 | 데이터 확충 효과만으로 새 방법이라고 주장하지 않음 |
| 개선이 EO encoder에 남는가? | frozen/joint, encoder만 이식해 새 연결부·reader 학습 | 공동 적응 시스템의 이점으로 주장 범위 축소 |
| 큰 학습과 다른 지역에도 통하는가? | 10k→100k 규모, 독립 지역·과제, 두 번째 VLM 계열 | 작은 과제나 특정 reader의 결과로 한정 |

최종 목표는 두 번째와 세 번째를 중심으로 네 번째까지 보여주는 것이다. 첫 번째는 데이터 구축 비용을 설명하는 보조 연구다. 모든 요소의 모든 조합을 전부 학습하는 거대한 factorial 실험은 하지 않는다.

## 3. 무엇으로 학습하는가

**첫 축은 공간 피복과 면적, 두 번째 축은 넓은 교란 영역이다.** LUCAS/TreeSatAI의 피복·산림 유형과 CEMS/WorldFloods의 침수 영역을 우선 검토한다. 원 관측·날짜·좌표·정답 지원 범위가 맞는 자료부터 사용한다. NEON은 현장 의미의 외부 검증, MTBS는 산불 확장 후보로 남긴다. 공개 자료 규모는 확보한 학습량이 아니다. 자세한 감독 수준·조건은 [출처 장부](../config/eo_vlm_expert_sources_v0_20260926.json)에 보존한다.

1. **원 EO 입력:** 실제 센서 밴드, 날짜, footprint, 유효 관측 mask. OlmoEarth가 받는다.
2. **검증 가능한 감독:** 현장/전문 매핑의 클래스·geometry·유효 시기, 프로그램으로 계산한 면적과 분모. LUCAS 폴리곤 밖을 음성으로 채우지 않는다.
3. **언어 감독:** 검증된 사실을 묻는 질문, 짧은 답, 관측·영역 참조, 판단 불가 사유. AI가 표현을 다양화할 수 있지만 원 사실을 바꾸지 않는다.

teacher에게만 보여준 정답 mask·현장 보고서는 일반 영상 판독 student의 입력에서 제외한다. teacher가 RGB에서 보지 못한 고사 원인·수질·기후 원인을 그럴듯한 문장으로 추가하지 못하게 한다. false-color를 넣어도 원 다중분광 정보를 모두 전달한 것은 아니다. 외부 현장 사실은 `field_reported`, 해당 영상에서 판독할 사실은 `image_supported`로 구분한다.

한 episode는 site×실제 관측 시점/기간×footprint다. 같은 영상의 질문 20개를 독립 영상 20개로 세지 않는다. 변화 과제는 실제 두 시점 이상의 정합과 변화 정답이 있을 때만 추가한다. 단일 피복 라벨에서 변화나 회복을 만들어내지 않는다. 개별 고사목·작은 해양 쓰레기는 해당 센서 해상도로 판독 가능한지부터 확인하는 별도 확장이다.

## 4. OpenRouter의 역할: 초안, 독립 확인, 필요한 사례의 검수

처음부터 모든 영상을 세 모델에 보내지 않는다. 아래는 10k 목표 corpus에 대한 **비용 측정 전 운영 초안**이다.

| 단계 | 대상 | 역할 |
|---|---|---|
| Teacher A | 학습 후보 전부 | 같은 원 관측/허용된 참조로 구조화 초안 생성 |
| Teacher B | 위험 우선 20% + 그 밖에서 무작위 5%p | A의 답을 보지 않고 독립 생성. 두 표본은 겹치지 않아 전체의 최대 25% |
| Teacher C | 전체의 최대 5% | 미해결·중요 사례의 추가 판독. 앞선 답을 본 중재와 독립 판독을 구별 |
| 코드 검증 | 모든 응답 | JSON, 좌표 범위, 단위, mask 면적, 원 출처 모순 확인 |
| 사람 검수 | 예산 안의 train/dev와 잠금 test | 학습 초안 교정 또는 모델 답을 가린 독립 판독 |

10k라면 A 10,000 + B 최대 2,500 + C 최대 500 = **최대 13,000번의 기본 호출**이다. 재시도·비용 보정·비교 실험은 별도이며, 5만 원으로 이 수량이 가능하다는 약속이 아니다. 공개 정답에서 결정적으로 만들 수 있는 수치는 API를 호출하지 않고 계산한다. 100k에 같은 비율을 자동 적용하지 않는다.

위험 점수는 teacher 불확실 응답, 수치–mask 모순, 라벨 유효일 불일치, 지역 중복/새 도메인 등을 쓴다. 위험 순위와 무작위 추출 seed는 사람 답을 보기 전에 고정한다. 합의 사례에서도 오류를 찾도록 무작위 표본을 반드시 남긴다. 미선정 사례는 '검증 통과'가 아니라 '자동 초안, 미검수'다.

**모델 다수결을 정답으로 저장하지 않는다.** 기존 참조와 충돌하면 참조 자체의 정합도 검토하고 unresolved를 허용한다. 공동 오답이 있을 수 있다는 근거는 [Correlated Errors in Large Language Models](https://arxiv.org/abs/2506.07962)에 있다. 이 연구의 수치를 EO에 그대로 적용하지 않고, 우리 표본에서 공동 오답·오류 상관을 별도로 측정한다.

공식 출처와 endpoint 차이는 [API 출처 JSON](../config/openrouter_annotation_sources_20260926.json)에 기록한다. 세 모델은 생성 후보이며 **학습용 출력 재사용 조건과 정확한 실행 endpoint가 모두 확정된 조합은 아직 없다.** 실제 후보 선정은 영상 판독 성능·총비용·출력 사용 조건을 함께 확인한다. 부적격 후보는 교체하며, 사용 조건 확인 없이 합성 라벨 학습을 시작하지 않는다.

동기식 이미지 API의 URL/base64 입력으로 고정된 RGB/false-color 패널을 보낸다. 원 GeoTIFF의 모든 밴드를 그 API가 직접 읽는다고 가정하지 않는다. 모델 ID·provider endpoint를 고정하고 fallback을 끈다. 지원되는 endpoint에서 JSON schema를 요구하고 응답을 로컬에서도 검증한다. 학습용 텍스트에는 `enforce_distillable_text` 필터와 원 제공자의 사용 조건을 확인한다. 온도 0도 완전한 재현성 보장은 아니다. [이미지 입력](https://openrouter.ai/docs/guides/overview/multimodal/image-understanding), [구조화 출력](https://openrouter.ai/docs/guides/features/structured-outputs), [공급자 선택](https://openrouter.ai/docs/guides/routing/provider-selection)

기록은 `model/provider/revision(가능한 경우)/quantization/prompt hash/image hashes/time/generation id/raw response/schema status/usage.cost`다. 출력 실패·재시도·보류와 비용도 남긴다. 실패한 답을 조용히 고쳐 성공으로 바꾸지 않는다. 모델별 영상 토큰화가 다르므로 실제 `usage.cost`로 보정한다. [사용량 회계](https://openrouter.ai/docs/cookbook/administration/usage-accounting)

Batch는 초기 설계에서 제외한다. 현재 이미지 URL 요구와 공급자별 지원·정책 옵션 차이가 있어 동기식 설정을 그대로 옮길 수 없다. 예상 예산에 batch 할인도 넣지 않는다. [공식 Batch 문서](https://openrouter.ai/docs/batch-quickstart)

### 저장할 라벨의 최소 계약

`episode_id, split, site_id, event_id, assets_and_hashes, sensor_bands, acquisition_time, label_validity, footprint_crs, valid_observation_mask, source_type, source_id, claims, teacher_runs, human_reviews, label_status`를 저장한다.

각 claim에는 `kind, value, unit, denominator, region_ref, observation_refs, observability, provenance`가 필요하다. 정답이 지원되지 않으면 값을 null로 두고 이유를 적는다. `label_status`는 원 출처만 검증됨 / AI 초안 / 사람이 수정함 / 독립 판독 확정 / unresolved를 구별한다. 독립 판독 확정도 전수 도메인 전문가 gold라는 뜻은 아니다. 긴 사고과정 대신 짧은 관측 근거를 저장한다.

## 5. 데이터 생성법을 평가하는 작은 별도 실험

공통 dev 감사 pool에서 세 정책을 비교한다: **강한 단일 teacher, 같은 계열 반복·자기 검토, 서로 다른 계열 검토**. 같은 영상·참조·출력 형식을 쓰고 실제 API 총지출 구간별로 오류–비용 곡선을 만든다. 호출 수만 맞춘 것을 동일 비용이라고 하지 않는다. 서로 다른 검수자의 답을 본 토론은 독립 투표가 아니다.

평가는 원 참조로 확인되는 상태/영역/수치 오류, unsupported claim, accepted-label 오류율, 답을 확정한 비율, 공동 오답, 검수 분당 수정된 오류 수다. 한 정책이 어려운 표본을 모두 버려 정확도만 올라가는 경우 coverage와 난도 분포를 함께 보고한다. 불일치로 뽑은 집합의 오류율을 전체 데이터 오류율로 쓰지 않는다. 모집단 추정은 별도의 무작위 표본 또는 알려진 추출 확률을 이용한다.

검수 우선순위는 random / uncertainty / disagreement+deterministic conflicts를 비교할 수 있다. 기존 train/dev 예산으로 만든 공통 판독 pool의 결과와 실제 소요시간을 이용한 **탐색적 replay**로 시작한다. 전체 pool에 답이 없으면 서로 다른 선택 집합의 오류 개수를 단순 비교하지 않는다. AI 초안을 본 train/dev 판독은 독립 gold가 아니므로 확증적 라벨 효율 개선이라고 부르지 않는다. 필요하면 일부 dev를 모델 답을 가린 판독으로 바꾸고 늘어난 시간을 먼저 반영한다. 이런 선택 방식은 이미 [원격탐사 active learning](https://arxiv.org/pdf/2212.01165)에도 선행이 있어 단순 불일치 선택을 새 알고리즘이라고 하지 않는다.

한 번 선택한 corpus와 라벨 revision을 동결해 모든 학생 모델에 똑같이 제공한다. test 결과를 보고 teacher·필터·threshold를 고치지 않는다. [MLLM-as-a-Judge](https://mllm-judge.github.io/)에서 보고된 판정 편향을 고려해 AI judge는 보조 지표로만 둔다. 주평가는 공통 참조와 독립 판독으로 계산한다.

## 6. 실제로 학습할 OlmoEarth–VLM

OlmoEarth Base 후보의 원 공간·다중분광 토큰 → EO 연결부 → **실제 pretrained VLM**의 언어 모델을 학습한다. 기존 RGB 경로를 함께 쓰되 모든 비교군의 입력 경로를 맞춘다. VLM/EO release, 센서 입력 규격, 학습 가능한 층·LoRA 범위는 구현 전에 확정한다. 처음부터 LLM 전체를 새로 사전학습하는 비용을 전제하지 않는다.

방법 후보는 공간 구획의 위치를 추적하는 토큰 압축과, 압축된 EO 토큰에서 지역별 피복/면적/근거를 회수하는 학습이다. encoder까지 gradient를 보낸다. 일반 caption 정렬이 잘되더라도 작은 영역이나 분광 구분을 잃을 수 있다는 것은 **검증할 가설**이지 OlmoEarth의 확인된 결함이 아니다.

후보의 구체화 순서는 다음과 같다.

1. 고정 토큰 예산에서 공간 구획·원 좌표에 대응하는 EO 토큰과 전역 토큰을 만든다. 원래 해상도·영역 지원 범위를 보존한다.
2. 같은 공개 mask/수치 라벨로 답변 loss와 공간 readout을 학습한다. 참조가 있는 영역에서만 loss를 적용한다.
3. 보존 학습 후보는 압축 뒤의 토큰에서 지역별 측정·근거가 회수되도록 직접 제약한다. 세부 head, loss 수식·정규화·가중치는 dev에서 정하고 본 실험 전에 고정한다.
4. 기존 EO replay/사전학습 목적을 사용하는 경우 일반 비교군에도 같은 관측·노출량으로 제공한다. EO 성능 보존 자체를 별도 결과로 측정한다.

**아직 loss 이름과 모듈 목록만으로 독립적인 방법 기여가 완성된 것은 아니다.** 일반적인 auxiliary segmentation/measurement head와 비교해 어느 정보가 어느 단계에서 더 잘 읽히는지를 보여야 한다. 강한 일반 head에 같은 유효 라벨을 제공하고, 더 많은 정답·더 큰 head를 준 효과와 구별한다. 후보의 수식과 가장 가까운 연결부/보존 학습 선행 비교는 구현 직전 남은 작업이다.

### 핵심 2×2: 같은 자료로 네 모델을 학습

| arm | EO 연결부 | 공간·수치 감독 방식 | EO encoder |
|---|---|---|---|
| A | 강한 일반 spatial resampler | 답변 + 일반 auxiliary readout | 공동학습 |
| B | 같은 일반 resampler | 답변 + 제안 보존 학습 | 공동학습 |
| C | 제안 공간 연결부 | A와 같은 일반 감독 | 공동학습 |
| D | 제안 공간 연결부 | B와 같은 보존 학습 | 공동학습 |

동일 관측·밴드·날짜·VLM·초기 EO·라벨/누락 mask·출력 형식·총 RGB+EO 토큰 수·입력 해상도·질문 분포·학습 순서·튜닝 기회를 준다. A도 같은 공간/수치 라벨을 실제 loss에 사용한다. 관측 격자·좌표·품질 mask와 정답 피복 mask를 구별하며, 제안 연결부만 정답 ROI를 입력받으면 안 된다. 질문이 지정한 ROI는 모든 군에 동일하게 제공한다. 감독 유무 차이를 알고리즘 차이로 포장하지 않는다. B가 A의 연결부에서도, C의 일반 head가 D의 연결부에서도 정의되어야 2×2다. 서로 분리할 수 없는 후보라면 2×2라고 부르지 않고 하나의 결합 방법과 적절한 ablation으로 다시 등록한다.

추가 연산·parameter·실제 GPU시간은 보고한다. 같은 step/epoch가 같은 FLOPs는 아니다. 최종 비교에는 공통 학습 노출량과 가능하면 동일 계산 상한의 보조 대조를 둔다. 공통 connector warm-up 후 EO 업데이트를 시작해 random connector의 초기 불안정 차이를 줄인다.

### encoder 기여는 별도로 확인한다

- A/D 각각 EO를 고정한 대조를 추가해 `A joint−A frozen`, `D joint−D frozen`을 비교한다. `D joint>A frozen`만으로 encoder 개선을 주장하지 않는다. 현재 OE1의 다른 구조를 이 frozen 대조로 대신하지 않는다.
- 원 pretrained EO, A로 학습한 EO, D로 학습한 EO에서 **encoder만 가져온다**. 학습된 연결부와 VLM 적응 가중치는 버리고 같은 초기화·학습량의 새 연결부/readout을 붙인다. VLM은 무작위 초기화가 아니라 동일 pretrained checkpoint의 새 사본이다. 새 지역·정답 조합의 적응 자료를 쓰고 잠금 test는 학습에 쓰지 않는다.
- 두 번째 pretrained VLM 계열과 별도 EO 분할/측정 probe에서도 같은 방식으로 비교한다. 새 연결부가 필요한 정상적인 적응 실험이며 zero-shot이라고 부르지 않는다.
- 개선이 이전 연결부와 함께일 때만 남으면 시스템 공동 적응으로 해석한다. 새 EO 표현 자체의 보편적 개선을 주장하지 않는다.

필수 외부 기준선은 **동일 EO 입력의 segmentation/measurement → 같은 LLM 설명**, RGB-only 실제 VLM, 질문/메타정보만 보는 모델이다. RGB-only는 정보가 적은 실용 비교이며 알고리즘의 공정한 주대조 A를 대체하지 않는다. EO 제거·관측 교체 진단은 입력별로 학습한 RGB-only/EO-only/both 대조와 함께 해석한다. OOD 입력 삭제의 실패만으로 EO의 가치나 시간 이해를 증명하지 않는다.

## 7. 규모와 실행 순서

| 단계 | 실행 | 조건과 해석 |
|---|---|---|
| 준비 | 원자료 20개, 세 teacher의 소량 비용·출력 검사, 사람 시간 측정 | train 보정용. 잠금 test로 재사용하지 않음 |
| 개발 | 10k corpus, 소규모 recipe/처리량 점검 | 준비 목표이며 확보량 아님. 개발 실행은 주 결과와 분리 |
| 본 비교 | 10k A/D 각 3 seed = 6회; 100k A/B/C/D 각 3 seed = 12회 | 먼저 총18회 핵심 본 학습을 계획. compute 견적 전 확정 발주 아님 |
| 귀속·전이 | 100k A/D frozen 각 3 seed = 6회, 새 reader/EO probe | 위18회 밖의 필수 주장 검증 비용. fresh readout 실행 수도 별도 장부 |
| 확장 | 1M A/D 각 3 seed = 추가6회 | 데이터·GPU 예산 확보 시. 1M을 포함한 core가 이전24회와 동일 |

따라서 초기 core18회에 frozen6회를 포함하면 **24회**, 조건부 1M6회까지 하면 **30회이며 fresh readout은 별도**다. EO→LLM, 입력별 학습 대조, teacher 비교, hyperparameter 개발, 데이터 노출량 대조의 비용도 별도다. 먼저 저렴한 공간·수치 probe로 점검하고 최종 encoder들에 새 VLM 적응을 수행하는 순서로 연산을 관리한다. 자원이 부족하면 작은 효과를 보고 유리한 셀만 반복하지 말고, test를 열기 전 실행 표를 축소한다. seed 3개가 검정력이나 모든 분야 일반화를 보장하지 않는다.

10k/100k는 동일 원천 혼합의 nested unique episode로 구성한다. 같은 epoch 곡선은 데이터와 계산을 함께 늘린 효과다. **10k를 반복한 조건과 100k 고유 관측 조건을 같은 노출량/계산 상한으로 비교**해 다양성 효과를 별도로 본다. 1M은 자동 실행 목표가 아니며 100만 원은 GPU 총 연구비가 아니다.

추가 사람 라벨 0/50/200개는 같은 train 관측 안에서 nested하게 공개하는 보조 비교다. 0도 공개 현장·전문 라벨을 포함할 수 있다. 방법 간 교정 전/후 라벨 교체 규칙과 반복 노출량을 같게 한다. 이것을 teacher정책×모든규모×모든학생의 전 조합으로 확대하지 않는다. 작은 dev 탐색 후 사전에 정한 대조만 본 실행에 넣는다.

## 8. 평가를 어떻게 잠그는가

대규모 공개 holdout은 성능 차이를 측정하고, **120개 독립 이중 판독**은 수치·근거가 맞는지 확인하는 작은 추가 평가로 쓴다. 두 역할을 섞지 않는다. 120개에서 3%p는 약 4개다. 독립 표본/정확도75% 가정의 단일 비율 95% 정규근사 반폭은 약7.7%p이며, paired 차이의 구간은 실제 두 모델의 불일치와 지역 군집에 따라 따로 계산한다.

평가 원천/과제 후보는 TreeSatAI의 산림 유형, CEMS/WorldFloods의 공간 침수 정답, 출처가 맞는 현장/교란 자료다. 입력–정답 정합을 확인한 뒤 최소 두 과제 계열·여러 독립 지역을 동결한다. 잠금 test 사례가 같은 원천의 train 파생물에 섞이지 않게 CEMS–WorldFloods 사건 alias까지 중복 확인한다. 공개 test가 pretrained 모델에 노출됐는지는 완전히 확인할 수 없으므로 '완전 미노출'을 단정하지 않는다.

주지표 후보는 **상태, 요청한 수치, 근거 영역이 모두 맞는 episode 비율**이다. 해당 과제에서 요청하지 않은 항목을 임의로 성공 처리해 섞지 않고 task별 적격 분모를 미리 정의한다. 수치 오차·영역 IoU·허용 관측 시점·최소 유의미 효과·EO 성능 비열등 한계는 원자료/pilot의 신뢰도를 보고 test를 열기 전에 고정한다. 현재 config에서는 미정(null)이며 확증 실행 가능한 사전등록으로 취급하지 않는다.

분해 지표는 영역 IoU/F1, 면적 오차와 signed bias, unsupported claim 비율, EO probe 성능, 관측 불가 판단의 정확도와 coverage다. 원 라벨의 부분 지원, 유효 영역, 구름/그림자의 영향을 나눠 보고한다. 평가 가능한 항목의 성능과 전체 라벨 확정률을 함께 제시한다. `관측 불가`라는 정답과 판독자끼리 미해결인 `라벨 미정`은 다르다.

원 판독 두 개와 조정 결과를 모두 남긴다. 전문가 시간이 모자라면 unresolved를 기록하고 표본을 조용히 삭제하지 않는다. 난해한 항목의 best/worst-case 민감도도 제시한다. test에서 모델명·AI 답·다른 사람 답을 숨긴다. 한 번 만든 공통 구조화 정답을 모든 모델에 적용하므로 사람 2명이 모든 모델의 긴 문장을 반복 채점할 필요는 없다.

주대조 D−A의 차이는 동일 episode에서 paired하게 계산하고 사이트/사건 단위 bootstrap 구간과 seed별 값을 보고한다. 질문을 독립 표본으로 부풀리지 않는다. B/C와 여러 보조 비교는 분석 순서·다중비교 처리 또는 탐색적 상태를 미리 정한다. 형식 오류·부당한 미응답을 성능 분모에서 지우지 않는다.

정답 위치·질문 어휘·장소/날짜만으로 풀리는지, 같은 질문에 실제 관측을 바꿔도 반응하는지 확인한다. 실제 변화 과제를 추가하면 같은 지역/계절의 무변화 대조와 관측 부족을 포함한다. D1 H의 합의 gate는 별도 연구의 기존 규칙이므로 이 OE2 평가에 임의로 옮기거나 소급 변경하지 않는다.

## 9. 100만 원 배분과 중단 조건

| 항목 | 계획 금액 |
|---|---:|
| 판독자 2인, 총60인시 ×12,000원 | 720,000원 |
| 도메인 검토 4인시 ×40,000원 | 160,000원 |
| OpenRouter 소량 시험·라벨 생성 상한 | 50,000원 |
| 수수료·재작업 등 나머지 예비비 | 70,000원 |
| 총액 | **1,000,000원** |

사람의 단가/가용성은 계획 가정이며 견적·채용이 확정된 것이 아니다. 사람 목표는 기존대로 train200(보정20 포함)/dev60/test120, 총380개다. 판독60인시 배분은 교육/pilot8 + test32 + train12 + dev4 + 재작업4이며, 전문가4인시는 별도다. 시간 실측에 따라 물량을 줄인다. 모든 표본에 전문가가 두 번 판독한다는 예산이 아니다.

API 5만 원은 기존 예비12만 원 안에서 나눈 **제안 상한**이다. 환전·결제 수수료와 재시도를 포함하고, 동시 실행 중 예상 지출까지 예약해 상한 전에 중지한다. 소량 가격 측정 후 가능한 호출 수를 정하며 100k 전체 호출을 이 예산에 약속하지 않는다. API 지출과 사람 비용을 중복 차감하지 않는다. 실행 계정·키·실제 환율/수수료·모델 사용 조건은 아직 확인하거나 설정하지 않았다. 새 API 지출은0원이다.

중단/축소 사유는 사전에 분리한다. 자료의 위치·날짜·정답 지원 범위가 불명확하면 그 자료의 학습을 멈춘다. 독립 사람이 해당 입력에서 판독하지 못하는 항목을 AI가 합의했다는 이유로 추가하지 않는다. 다중 AI가 같은 비용의 단일 teacher보다 낫지 않으면 단일 teacher로 간소화한다. D의 이점이 새 reader/EO 과제에 남지 않으면 encoder 개선 주장을 접는다. 주대조가 불확실하면 그 상태로 보고하며 성공 문턱을 사후 변경하지 않는다.
