# 오름 변화 사람 판독 — 라벨 정의서 v1 (2026-09-22, 확정 후 변경 금지)

> 이 문서는 라벨을 찍기 **전에** 고정한다(GOAL.md L4). 찍는 중에 정의를 바꾸고 싶어지면 메모에 적고 계속 찍는다 —
> 바꾸는 건 v2에서 한다. 관련 계획: `docs/PLAN_JEJU_OREUM_STUDIO_2026_09_22.md` WP0/WP1.

## 1. 무엇을 판단하나

**질문 하나**: "이 오름의 320 m 창에서, 2025년 장면과 2026년 장면 사이에 **지표(땅 표면)가 실제로 달라졌는가?**"

- 단위 = 오름 1곳 × 사건 쌍(2025→2026, 같은 계절 Sentinel-2 장면). 프레임 날짜는 상세 화면 캡션에 있다.
- 근거 = (1) 전후 프레임(누르면 전환) (2) Δz 토큰 맵(어디가 깃발인지 — **참고만**, 라벨은 임베딩을 설명하지 않는다)
  (3) VWorld 항공사진(현재 모자이크, 촬영 시점 비공개 — "지금 무엇이 있나"용) (4) 월별 시계열·NDVI(여러 해 지속 여부).
- 라벨은 **임베딩 점수를 맞추는 게 아니다.** 점수가 높아도 아무것도 안 보이면 c나 d다. 점수가 낮아도 보이면 a다.

## 2. 코드 4개 (키 a–d)

| 코드 | 이름 | 이렇게 보이면 | 흔한 함정 |
|---|---|---|---|
| **a** | 실질 변화 | 두 해 프레임에서 **같은 자리**가 다르게 보이고(나지 생김·건물/도로 생김·식생 사라짐), 항공사진에서도 그 흔적이 있다 | 계절 색 차이(초록↔갈색 전체)는 a가 아니다 — 창 전체가 아니라 **국소**여야 한다 |
| **b** | 지속 인공물 | 두 해 **모두** 같은 시설·도로·건물이 있다. 깃발은 섰지만 연간 변화가 아니다 | 상세의 "지속 토큰" 수가 크면 b 후보. 그래도 눈으로 확인 |
| **c** | 대기·구름 | 구름 가장자리·해무·그림자·계절 차이로 한 해 프레임이 흐리거나 색이 다르다 | 프레임 한쪽이 뿌옇거나 창 판독률(캡션)이 낮으면 c 우선 |
| **d** | 판독 불가 | 위 셋 중 무엇인지 **말할 수 없다** | d는 실패가 아니다. 단, **이유 메모 필수**(구름 / 해상도 / 연도 불명 / 그늘 …) — 다음 라운드 데이터 요구사항이 된다 |

우선순위(둘 이상 보일 때): **a > b > c**. 즉 어딘가 실질 변화가 있으면 구름이 있어도 a. 확신이 없으면 d.

## 3. a에만 붙이는 태그 (키 1–6, 하나만)

| 키 | 태그 | 뜻 | 출처 |
|---|---|---|---|
| 1 | `trail_erosion` | 탐방로 주변 나지 확대·침식 | 제주도 오름 훼손 등급제(2026-04): 3등급 = 침식 15–30 cm·뿌리/암석 노출, 4–5등급 = 자연휴식년제 |
| 2 | `veg_loss` | 병해·기후·산불 등 식생 손실 | IUCN World Heritage Outlook 제주(2025) 기후 위협 |
| 3 | `facility` | 새 시설물·도로·개간·건축 | 개발행위허가 86건(한국 지정 레이어)과 대조 가능 |
| 4 | `grazing` | 방목·경작·초지 관리 변화 | 오름 초지 특성 |
| 5 | `coastal` | 해안 침식·붕괴 | IUCN(성산일출봉·송악산) |
| 6 | `other` | 위 어디도 아님 | **메모에 무엇을 봤는지 필수** |

태그는 "원인 판정"이 아니라 "무엇이 보였나"다. 원인은 현장·행정자료가 정한다.

## 4. 대상 60곳 + 재판독 5곳 (`apps/oreum-web/public/data/label_targets.json`, sha `3c73480de8e2…`)

- **상위 30**: v8 순위 1–30 (문도지·금오름·도너리·세미소·칡·누운·모구리·새신·본지·여절악·가마·밝은·정물·남산봉·마중·민오름×2·왕이메·당·설 …).
- **대조 30**: 채점됐지만 깃발율이 채점 중앙값(1.74%) 미만인 오름에서 무작위(seed 20260922). 대조군에 **문석이오름(자연휴식년제)** 이 들어갔다 — 순위가 낮은데 훼손 오름이면 그 자체가 발견.
- **재판독 5**: 당산봉·별도봉·소수산봉·은월봉·칡오름. 60곳을 다 찍은 뒤 "재판독" 버튼을 켜면 첫 라벨이 가려진 채 다시 보인다. 두 번의 코드 일치율이 이 정답의 신뢰 구간이다.
- 관측 불가 90곳은 대상이 아니다("점수 없음 ≠ 변화 없음" 규율, 분모 유지).

## 5. 절차 (당신이 할 일, 3~4시간)

```bash
cd apps/oreum-web
nvm use 22            # Next 16 은 Node 20+ (설치돼 있음: v22.18.0)
pnpm install          # 처음 한 번 (pnpm 10 은 npm i -g pnpm@10 으로 이미 설치)
NEXT_PUBLIC_VWORLD_KEY=$(grep VWORLD_API_KEY ../../.env | cut -d= -f2) pnpm dev   # 항공사진 켜려면 키 필요
# → http://localhost:3400
```

1. 오른쪽 레일 **상위 30**부터 위에서 아래로. 오름을 누르면 상세가 뜬다.
2. 전후 프레임을 눌러 두 해를 번갈아 본다 → Δz 맵으로 깃발 위치를 본다 → **"항공사진으로 확대"** 로 그 자리에 지금 무엇이 있는지 본다 → 월별 시계열에서 그 변화가 지속되는지 본다.
3. 키 **a/b/c/d**. a면 **1–6** 태그. d면 메모에 이유. 저장은 자동(localStorage).
4. **대조 30**도 같은 눈으로. 대조군에서 a가 나오면 특히 메모를 자세히.
5. 60/60이 되면 **"재판독"** 버튼 → 목록에 "재" 표시 5곳만 진하게 보인다 → 첫 라벨을 모르는 채 다시 찍는다.
6. **"내보내기"** → `labels.json` 다운로드 → `apps/oreum-web/public/data/labels.json`으로 옮기고 커밋:
   ```bash
   mv ~/Downloads/labels.json apps/oreum-web/public/data/labels.json
   (cd apps/oreum-web && pnpm check)      # 명단·태그·d 메모·재판독 규칙을 빌드가 검사한다
   git add apps/oreum-web/public/data/labels.json && git commit -m "오름 사람 판독 v1: 60곳 + 재판독 5"
   ```
   브라우저를 바꾸거나 캐시를 지우면 localStorage가 사라지니 **중간에도 한 번씩 내보내기**를 눌러 두는 게 안전하다.

## 6. 판독 규칙 (헷갈릴 때)

- **국소 vs 전체**: 창 전체 색이 바뀐 건 계절/대기(c). 한 덩어리·한 줄이 바뀐 건 a 후보.
- **항공사진은 "지금"만 보여준다**: 두 해 프레임에서 변화가 없는데 항공사진에 시설이 있으면 b(지속 인공물). 항공사진만 보고 a를 찍지 않는다.
- **Δz 깃발이 여기저기 흩어져 있으면** 대개 c. 모여 있으면 a나 b.
- **NDVI가 여러 해 계속 떨어지면** veg_loss 후보. 한 해만 낮으면 가뭄·해무일 수 있다.
- **뉴스는 맥락이지 근거가 아니다.** 기사 때문에 코드를 바꾸지 않는다.
- 확신 없으면 d + 이유. d가 30%를 넘으면 빌드 검사가 막는다 — 그건 당신 잘못이 아니라 근거 자료가 부족하다는 신호다.
