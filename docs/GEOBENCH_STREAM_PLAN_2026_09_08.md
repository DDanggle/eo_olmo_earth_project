# GEO-Bench-Stream 플랜 (2026-09-08) — 갱신형 캐시를 GEO-Bench-2 위 시간 축 확장으로 올림

요지: 새 데이터셋을 만들지 않음. GEO-Bench-2의 공식 프로토콜(시점별 인코딩 → 평균 → 디코더)이 "정지된 세계"를 가정하므로, 같은 데이터·split·디코더·지표 위에 **관측 도착 순서대로 상태를 갱신하는 평가 규약 한 겹**을 올림.

## 프로토콜(고정)
- 상태 s_k: cutoff k까지의 관측을 본 임베딩(초기 상태는 전체 인코딩, 모든 팔 동일)
- 도착 o_{k+1}: 다음 관측의 단일 취득 임베딩(센서는 데이터셋이 주는 대로)
- 교사 e_{k+1}: cutoff k+1까지 전체 재인코딩(상한·비용 기준)
- 판독기: 교사 위에서 공식 프로토콜로 학습·동결, 모든 팔에 동일 적용
- 지표: 과업 지표 절대값 / 회복률 (팔−무갱신)/(교사−무갱신) / 실측 비용(GPU-s·읽기·저장, 배치 구현 명시) / 시점 라벨 과업은 지연·오경보
- 기준 팔: 재인코딩·무갱신·단일 평균·EMA·관측 0 GRU·GRU·GRU+Δt
- 일반화 단위: 공식 split(사건/지역), 갱신기 seed 3 × 판독기 seed 3

## 과업 순서
1. KuroSiwo(S1 전·전·후, 43사건) — 진행 중, 사전등록 동결(통과 80%, 관측 0 ≤20%)
2. Sen12 교차 센서(S2 상태 + S1 asc 새 영상) — 원본 보유(13,306 S1 파일), 추출기 작성 필요
3. DynamicEarthNet(주별, 월별 라벨) — 변화 지연·오경보 축, 시점별 재추출 필요
4. Fields of the World(2 window) — 한 단계 갱신
5. PASTIS-R / BioMassters — sha256 재해결 후 긴 시계열·회귀
6. AI-Hub 한국 3-task — 갱신 1회가 여러 판독기에 유용한가(라벨 개봉 1회)

## 채택 조건(사전 고정)
외부 과업 ≥3에서 GRU 회복률 ≥80% & 관측 0 ≤20% → 본회의 시도. 2개 → EarthVision/저널. ≤1 → 특성화 논문. Δt 조건은 외부에서도 ≥+2%p 일관일 때만 본문.
