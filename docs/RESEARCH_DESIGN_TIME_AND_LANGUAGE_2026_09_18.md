# 연구 설계 — 시간축 극세화 트랙(T) + 언어 접지 트랙(L) — 2026-09-18

작성: 2026-09-18. 상태: 설계·미등록. 사용자 요청 "두 아이디어를 학습까지 포함해 극대화". 근거는 MS-122~124(frozen OlmoEarth 결정 강건성, 손실은 사건 후 증거 제거뿐), 기존 자산 R1~R10, 읽기 목록. 문헌 항목 중 "미확인"은 초록·이름만 본 것.

## 0. 먼저 결론

- 두 트랙 모두 학습 가능하고 2 GPU 안에 들어감. 그러나 10주 안에 CVPR 한 편이 되는 것은 **T 하나**뿐임. L은 학습·평가 세트 구축이 먼저라 이번 사이클에는 workshop/Ai2 연구 산출물이 상한임.
- T의 핵심 전환: "시간 해상도를 올린다"를 **라벨 없이 어디서나 측정 가능한 문제**로 바꿈. 관측하지 않은 날짜의 잠재 상태를 이웃 관측에서 복원하는 **latent temporal interpolation**. 정답은 held-out 실제 관측의 임베딩이므로 라벨이 필요 없음. 이것이 "1,3으로 2"의 잠재공간 판이고 LIANet(픽셀)과 다름.
- L의 핵심 전환: 임베딩을 문장으로 바꾸는 것이 아니라 **구조화 속성·변화 유형을 학습으로 뽑고, 그 위에 LLM 투영(projector)을 학습해 접지된 변화 주장을 생성·검증**하는 것. 지역 맥락은 공공기록 RAG로 붙임. 평가 지표는 주장 정밀도와 환각률.

## 1. 트랙 T — 시간축 극세화 (연구자 관점)

### 1.1 질문 사다리 (아래로 갈수록 방법)

| # | 질문 | 측정 | 라벨 | 상태 |
|---|---|---|---|---|
| T0 | 사건 후 관측 몇 장에서 readout이 켜지는가 | postkeep k=0..3, postlast1, ctrl의 IoU·탐지율 곡선 | Sen12 | **v3 실행 중(2026-09-18)** |
| T1 | 같은 달 두 관측을 모델이 구분하는가 | 관측 A 단독 vs A+B(같은 달) 토큰 cos·readout 변화 | 없음 | 미실행, 10분 |
| T2 | 관측하지 않은 날짜의 잠재 상태를 이웃에서 얼마나 복원하는가 | held-out 관측 임베딩 대비 cos/MSE, 간격 Δt별·계절별 | 없음 | **T의 벤치마크 본체** |
| T3 | 복원한 상태가 readout에 쓸모 있는가 | 사건일 직후 가상 날짜의 복원 상태 → readout AP vs 실제 관측 상태 | Sen12·Kuro | T2 후 |
| T4 | 학습된 연속시간 보간기가 단순 보간을 이기는가 | T2·T3에서 nearest / 선형 / GRU(MS-116) / Δt-GRU / neural-ODE / 제안 | 없음+Sen12 | 방법 |
| T5 | 촘촘한 스트림(S2+S1 별도 상태)에서 탐지 지연이 줄어드는가 | 사건일→첫 탐지까지 일수, 센서별 상태 + 확률 결합 | Sen12(S1 asc 보유) | MS-118/121 교차센서 갱신 실패를 우회: 센서별 상태 분리 |

### 1.2 T2 벤치마크 정의 (라벨 무관, 전 지역)

- 단위: 타일 × 관측 시퀀스(실제 취득일). 창 안 관측 하나를 가리고, 나머지로 그 날짜 t*의 잠재 상태를 예측.
- 정답: `E0(전체 창)`이 아니라 **가린 관측을 포함한 창의 E0 상태**(teacher). 이유: 모델이 그 관측을 봤을 때의 상태가 "그 날짜의 표현".
- 조건 축: 간격 Δt(5일~6개월), 구멍 위치(시작/중간/끝), 계절, 지역, 센서(S2/S1), 사건 유무.
- 지표: 잠재 cos·MSE, readout 결정 flip rate(라벨 없음), 라벨 있으면 AP.
- 기준선: nearest-obs 상태, 선형 잠재 보간, 평균, EMA, GRU updater(MS-116 그대로), Δt-GRU(MS-116-arch).
- 데이터: Sen12 15지역 13,626타일 15시점(S1 포함), KuroSiwo 7,000, Korea AI-Hub v2 2,536칩(라벨 봉인·시간축 확인 필요), Solar 4시점(부적합).

### 1.3 T4 학습 설계

- 입력: 이웃 관측들의 단일 임베딩(E0 single, 이미 추출 경로 있음) + 실제 날짜.
- 모델 후보: (a) Δt 조건 GRU(기준), (b) 연속시간 잠재 ODE/flow(θ가 Δt 함수), (c) 시간 어텐션 + day-of-year 연속 부호화. 인코더 고정, 학습 파라미터 ≤ 수백만.
- 손실: teacher 잠재 MSE + semigroup 일관성(Φ_{a+b}=Φ_b∘Φ_a) + 선택적 readout logit 보존(MS-116에서 지역별 효과 갈림, ablation).
- 사전학습 접근은 하지 않음. 이유: MS-122~124가 frozen 표현 자체의 결함을 못 찾았음. 결함은 "관측이 없는 날짜의 상태가 없다"이지 "있는 관측을 잘못 읽는다"가 아님.
- 자원: GPU1 학습(4폴드 × 3시드 × 3모델 ≈ 3일), GPU0 추출·평가.
- kill gate(등록 예정): 선형 잠재 보간 대비 학습 모델의 cos 개선이 부트스트랩 CI 밖이 아니면 방법 주장 철회, 벤치마크만 남김.

### 1.4 T5 지역 극세 스트림

- 특정 좁은 지역(hiroshima 또는 제주)에서 S2 전 관측 + S1 asc 전 관측을 실제 날짜로 정렬한 스트림을 만들고, 센서별 상태를 각각 갱신, readout 확률을 늦게 결합.
- 결과물: 사건일 기준 "첫 탐지까지 일수" 분포(T0의 장 수를 일수로 환산). 구름으로 S2가 비는 구간에서 S1 상태가 지연을 줄이는지가 질문.
- 주의: MS-90 naive fusion 게이트 실패 기록 있음. 결합 규칙은 학습 없이 등록된 단순 규칙(max/mean)만 먼저.

### 1.5 T 일정(10주)

1주 T0·T1·T2 추출(gap arm 재사용) → 2~3주 T2 벤치마크 표 + 기준선 → 4~6주 T4 학습·ablation → 7주 T3·T5 → 8~10주 확증 시드·비용·집필. R8 clean 확증은 3주차 병렬.

## 2. 트랙 L — 임베딩을 언어가 직접 학습한다 (EarthTalk: OlmoEarth → OLMo)

갱신 2026-09-18: 사용자 방향 반영. 임베딩을 속성으로 풀어 템플릿화하는 것이 아니라, **LLM이 OlmoEarth 토큰을 입력으로 받아 직접 학습**한다. Ai2 스택(OLMo LLM, Molmo의 projector+LLM 레시피, OlmoEarth)을 그대로 쓰는 것이 Ai2 방향성과 맞는다는 판단. 단 "Ai2가 이 결합을 계획한다"는 근거는 없음(추정).

### 2.1 문제 정의

> frozen OlmoEarth의 저장 토큰(공간 격자 × 시간 상태)을 LLM의 입력 토큰으로 투영해, 픽셀을 다시 보지 않고도 지역·시간 맥락이 반영된 서술·질의응답·변화 주장을 생성하고, 그 주장이 접지되는가.

세 가지가 논문 질문임. (a) 캐시된 EO 임베딩만으로 언어 과업이 되는가(픽셀 VLM 대비). (b) 시간 변화 추론이 되는가(픽셀 VLM이 약한 축). (c) 캐시 위 언어는 얼마나 싼가(EarthCache 서사와 연결: 재인코딩 없이 질의).

### 2.2 모델

```
OlmoEarth(frozen) → 토큰 격자 768×32×32 (창 t0), 768×32×32 (창 t1)
  → 공간 풀링/리샘플 → K개 EO 토큰(예: 64+64) + Δ 토큰(t1−t0, 64)
  → Projector(MLP 2층, 학습) → OLMo 임베딩 공간
텍스트: 장소명·행정단위·날짜·센서·구름비율·공공기록 발췌(RAG)
OLMo-7B(LoRA) → 답변: 서술 / QA / 변화 주장(타일·사분면·날짜·유형·근거)
```

- Molmo/LLaVA 계열 구조와 같음. 차이는 입력이 픽셀 인코더가 아니라 **재사용 가능한 캐시 토큰**이고, 시간 축(두 창 + Δ)이 1급 입력이라는 점.
- 시간 상태는 트랙 T의 산출(갱신·복원 상태)을 그대로 넣을 수 있음. T2 복원 상태로 "관측 없는 날짜의 서술"도 가능해짐(검증 필요).

### 2.3 학습 3단계

| 단계 | 학습 대상 | 데이터 | 규모·비용 |
|---|---|---|---|
| S1 정렬 | projector만 | 타일 자동 캡션: WorldCover·Dynamic World·OSM·DEM·Hansen에서 구성 비율·객체·지형을 문장화(템플릿+OLMo 패러프레이즈). 전 지구 무료. | 50만~100만 타일, GPU1 1~2일 |
| S2 지시 튜닝 | projector + OLMo LoRA | 변화 QA·순서·사분면 접지·수량·비교 질문. 정답은 지도 전이·Sen12/Kuro 사건·AI-Hub 라벨(봉인 해제 후)에서 자동 생성. | 5만~20만 쌍, GPU1 2~3일 |
| S3 지역 맥락 | LoRA 소량 + RAG 프롬프트 | 한국 공공기록(산지전용·개발행위·보호구역·태양광 허가) 시점·좌표 결합, 제주 사람 검수 100~200건 | 수천 쌍, 반나절 |

원칙: 사람 캡션 없이 시작함. 합성 라벨은 **지도에서 나온 사실**로만 만들고, 평가는 사람 검수 세트로 분리함. "파괴"는 학습 라벨이 아니라 규칙+기록 조합(예: 보호구역 내 식생 소실 + 허가 없음)으로 S3에서만 등장.

### 2.4 평가와 기준선

- 벤치마크: EO-Change-QA(가칭). 항목당 (타일 쌍, 질문, 정답, 근거 마스크). 지표: 정답률, 접지 IoU(주장한 사분면/영역 vs 근거), 환각률(근거 없는 주장), 시간 순서 정확도, 기록 인용 정확도.
- 기준선(모두 이겨야 기여): Molmo/오픈 VLM에 RGB 전후 칩 입력, 텍스트 메타만 넣은 OLMo, L1/L2 속성 헤드 + 템플릿(LLM 없음), 캐시 토큰 대신 무작위 투영.
- 비용 표: 질의당 재인코딩 없는 캐시 경로 vs 픽셀 VLM 경로의 GPU 초·I/O.

### 2.5 신규성·리스크

- 점유됨: 영상→텍스트 EO VLM(GeoChat·TEOChat·EarthDial 계열, 미정독), CLIP류 정렬, EO 에이전트.
- 후보 기여: (1) frozen EO FM 캐시 토큰을 LLM 입력으로 쓰는 첫 체계적 평가와 픽셀 VLM 대비 손익, (2) 시간 Δ 토큰과 변화 접지 벤치마크, (3) 공공기록 결합 지역 맥락. 문헌 정독 후 (1)이 이미 있으면 (2)(3)으로 좁힘.
- 리스크: 40 m 토큰이라 소형 객체 서술 불가(MS-119/120과 일치). 합성 캡션 편향을 LLM이 외움. OLMo LoRA 학습이 GPU1을 T4와 나눠 써야 함. 사람 검수 0건에서 시작.
- 이번 사이클 상한: S1·S2 학습과 벤치마크 v0(자동 라벨) + 사람 검수 100건 → workshop급. CVPR main은 다음 사이클.

### 2.6 L 일정

1주 자동 캡션 생성기(지도→문장) + 캐시 토큰 풀링 계약 → 2주 S1 → 3주 QA 생성기 + S2 → 4주 기준선(Molmo·텍스트만) + 벤치마크 v0 → 5주 S3 한국 기록 + 검수 100건 → 6주 환각률·비용 표.

## 3. 두 트랙의 관계와 자원 배분

- T가 L의 입력(시간 상태·변화 Δ)을 만듦. L의 Δ 토큰은 T2 복원 상태로도 계산 가능.
- GPU1: T4 학습(4~6주), 그 외 기간 L3 LoRA. GPU0: 추출·평가·L1·L2.
- 사람 시간: T는 코드·분석, L은 라벨 검수가 병목. 검수 인력이 없으면 L은 2.4 기준선까지만.

## 4. 즉시 실행 중·다음

- 실행 중: T0 (prereg v3, hiroshima·indonesia).
- 다음 등록: T1(10분), T2 추출 계약(가릴 관측 선택 규칙·teacher 정의 동결).
- L은 자동 캡션 원천(WorldCover·Dynamic World·OSM) 타일 정합 감사와 캐시 토큰 풀링 계약부터.

### 5.2 심사자 반론과 답

- "TEOChat에 같은 영상을 주면 되지 않나" → 답은 실험뿐. 캐시 토큰이 이기는 축(12시점·S1·비용)과 지는 축(소형 객체·정밀 위치)을 같은 표에 냄. 지는 축을 숨기면 탈락.
- "RAG로 충분하지 않나" → RAG는 유사 사례 검색이지 그 타일의 시간 변화 서술이 아님. 같은 질문 세트에서 RAG-over-cache를 기준선으로 두어 증명.
- "합성 캡션을 외운 것 아닌가" → held-out 지역·사람 검수 세트, 지도 라벨과 상관 없는 질문(사건 시점) 포함.
- "T2는 그냥 보간 아닌가" → 선형 잠재 보간이 기준선이고 kill gate. 이기지 못하면 벤치마크만 남김.
- "MS-125의 최신 1장 열세는 산사태 특성" → 맞을 수 있음. KuroSiwo(홍수)에서 반대면 그것이 결과. 과업별 곡선을 냄.

### 5.4 갱신된 판단

- T: MS-125로 "사건 후 2장" 곡선이 나와 스트리밍 갱신의 동기가 처음으로 정량화됨. 논문 몸통 = 갱신형 캐시(R7/R8) + T2 잠재 보간 벤치마크 + MS-122~125 강건성·지연 열. 10주 안에 닫을 수 있는 유일한 구성.

## 7. G-T4 재해석과 T2b (2026-09-19)

- MS-132: 단일 관측 임베딩의 반복성 상한이 ≤10일 쌍에서 cos .848이고, 학습 보간기는 test 지역에서 그 지역 상한(.75~.78)을 넘어 .82~.86에 도달. G-T4의 "+.03 미달"은 문턱을 노이즈 상한 없이 정한 설계 오류이며, 규칙은 사후 변경하지 않되 결과는 "선형 대비 +.03 = 측정 가능한 headroom 전부"로 보고.
- **T2b 계약(등록 예정)**: 정답을 held-out 단일 관측이 아니라 (a) 그 관측을 포함한 teacher 창 상태(`olmo_streaming_dev/teacher_fp16` cutoff 상태 또는 재추출), (b) 봉인 readout의 그 날짜 출력으로 바꿈. 기준선은 동일(선형·nearest·mean_all·GRU). 이 설정에서만 "관측 없는 날짜의 지도"라는 논문 질문이 직접 측정됨.
- **T5 지역 고정·시간 분할**: 사용자 요청 "좁은 지역을 촘촘히"는 hiroshima(상한 .906, 관측 밀도 높음)에서 시간 분할로 수행. 지표는 MS-125의 사건 후 탐지 관측 수 단축. 짧은 간격 보간은 이득이 가장 작은 구간(≤20일 +.017)이므로 주 목표로 삼지 않음.

## 8. 재설계 — 관측 교정형 지역 상태 (2026-09-19, 문헌감사 §4·§6 채택)

문헌감사(`REGIONAL_CONTINUOUS_EO_LITERATURE_AUDIT_2026_09_18.md`)의 정정 5건을 장부에 반영했고, §7의 "상한 도달" 해석과 T2b 우선순위를 철회함. 논문 질문을 다음으로 바꿈.

> 지역의 과거를 학습한 EO 상태 모델이, 불규칙하게 도착하는 새 관측으로 상태를 교정하여, 같은 오경보 수준에서 실제 변화를 더 빨리 확인할 수 있는가?

### 8.1 보여야 할 "기존 모델의 구체적 실패" (우리 실측에서 이미 보이는 것)

| 실패 | 근거 | 왜 실패인가 |
|---|---|---|
| F1 pooling 희석 | MS-125/133: 사건 후 1장 포함 시 IoU가 control의 21%, 탐지율 .59 | 새 영상에 흔적이 선명해도 11장 옛 관측과 평균되어 신호가 1/12로 희석. 두 번째 관측(중앙값 25일)까지 기다려야 함 |
| F2 월 해상도 | MS-127: 같은 달 두 관측 순서 무시, 둘째 장 기여 없음 | 5일 재방문을 넣어도 월 index가 같으면 구분 못 함. 촘촘한 스트림의 정보를 버림 |
| F3 최신 관측 단독의 불안정 | MS-125 postlast1 5~16% | 최신 1장만 읽는 head는 흔적 감쇠·관측 잡음에 취약. "그냥 최신 영상만 보면 되지 않나"의 반례 |
| F4 사건 없는 구간 오경보 | MS-133 사건 전 탐지율 .31(픽셀 1개 기준) | 갱신 모델은 이 오경보를 늘리지 않으면서 F1을 고쳐야 함 |

F1과 F3이 한 쌍임. 옛 기억을 전부 평균하면 늦고(F1), 기억을 버리면 흔들림(F3). 그 사이를 **관측 교정**이 메워야 한다는 것이 방법의 자리임.

### 8.2 "확인해서 업데이트"의 구체적 구현 (기존 자산 위에서)

```text
상태 h⁺_{i−1}(768×32×32, 시작은 사건 전 창의 E0 상태)
  전개  h⁻_i = Φ(h⁺_{i−1}, Δt_i, doy_i, region)          ← MS-116 GRU/Δt-GRU 재사용, 기본은 항등
  관측  e_i = E0_single(I_i)                                ← 이미 추출된 single_fp16
  혁신  r_i = e_i − H(h⁻_i)                                 ← H는 학습 선형 사상(창 상태→단일 관측 예상)
  게이트 g_i = σ(MLP[r_i, q_i(구름·SCL), Δt_i])              ← 품질 낮으면 작게, 큰 혁신은 억제하지 않음
  교정  h⁺_i = h⁻_i + g_i ⊙ K(r_i),  u_i = 불확실성(혁신 크기·품질·Δt 누적)
  판독  readout(h⁺_i) → 변화 확률, "관측됨/예측됨" 표시, 근거 관측 목록
```
- 학습 목표: (a) h⁺_i가 "그 시점까지 관측을 포함한 전체 재인코딩 상태"를 닮도록(teacher, MS-116과 동일), (b) 사건 후 첫 관측에서 readout이 켜지고 사건 전 구간에서는 안 켜지도록(고정 오경보 예산 하의 지연 손실), (c) 급변을 지우지 않도록 smoothness는 정상 구간에만.
- 기존 MS-116 GRU와의 차이는 단 두 가지: 품질·혁신 조건부 게이트, 불확실성 출력. 이 둘이 Δt-GRU를 못 이기면 방법 주장 없음(감사 §6.4).
- 조건부 입력: 실수 Δt(일), day-of-year, 지역 코드, SCL clear fraction, 관측 여부. 기상은 v1 제외.

### 8.3 첫 실험 P1 (등록 예정, 감사 §6 프로토콜)
- 지역: hiroshima. 분할: train=사건 전 기간 전체+사건 후 초반 일부 타일(공간 block), val=다음 기간, test=미사용 미래 기간·다른 공간 block. purge 적용.
- 입력 계약: top-12 맑은 장 선택을 버리고 **실제 도착 순서의 전 관측**(15장, SCL 포함)을 씀. causal arm은 미래 관측·품질을 못 봄.
- 기준선: last-obs head, EMA, running mean, Δt-GRU(MS-116), 전체 접두 재인코딩(비용 기준). 변화 경보 고전 기준선(seasonal residual)은 v1.
- 지표: 고정 오경보/km²에서 사건 확인 지연(일), 사건별 확인 성공률, 위치 IoU, 불확실성 calibration, 도착당 비용.
- 통과 규칙(등록 시 확정): 같은 오경보에서 Δt-GRU 대비 확인 지연 중앙값이 짧고 CI가 0 제외, 사건 전 오경보 증가 없음.

- 우선 정독: SPEAR NeXT, LIANet, AnytimeFormer, S-CCD, LAINR.

## 9. 2차 검토 반영 (2026-09-19 저녁) — 조건부 GO, 우선순위 4개

§8.1의 실패 표는 다음으로 낮춤. F1 "초기 사후 관측에서 낮은 IoU(원인 미확정)", F2 "같은 달 추가 관측 기여가 작음(이 계약 한정)", F3 **철회**(postlast1은 사전 관측 유지), F4 유지. "F1–F4 입증 → 방법만 만들면 됨" 단계가 아님.

### 9.1 P1 v0.1에 추가할 arm과 지표 (v0 규칙은 사후 변경 없음)
- `latest_head`: 최신 관측 1장만 입력, 그 표현에 맞춘 작은 head를 train 블록 라벨로 학습(진짜 latest-only 대조).
- `meta_only`: 관측 없이 Δt·day-of-year·지역만으로 상태를 전개하는 대조(사건 시기 암기 검출).
- 지연 두 종: 사건일→확인, 첫 유효 사후 관측(구름 <.5 제외)→확인. 확인 성공률·미탐지 수를 항상 함께 보고.
- 사건 전 오경보 예산은 검증 블록에서 arm별 고정(v0와 동일).

### 9.2 학습 목표 분리
- Teacher MSE는 **보조 목표**(기존 readout 호환 유지)로 가중치를 낮춤.
- 주 목표는 근거 기반 확인: 새 유효 관측에서 변화 근거(마스크·위치)를 맞히는 supervision과, 검증 오경보 예산 하의 조기 확인 손실. "첫 사후 관측에서 무조건 켜기"는 금지(구름 관측이면 보류가 정답일 수 있음).
- 불확실성은 혁신 크기 이름표가 아니라 오류·보류와 연결되는지 calibration·risk–coverage로 검증.
- 선행(KalmanNet, EO 재귀 분류)이 있으므로 품질 게이트+불확실성만으로 신규성을 주장하지 않음.

### 9.3 사건 단위 외부 평가
- hiroshima는 개발 사례. 외부 확인은 타일 추가가 아니라 **사건 통째 holdout**(itogon 2018-09, thrissur 2018-08, hokkaido 2018-09 등). 타일 bootstrap CI와 사건 일반화 CI를 분리.

### 9.4 VLM 논문과의 연결: 교정기는 하위 모듈
```
교정된 공간 상태 + 보존된 사건 근거(위치·날짜·품질)
  → 질문 조건부 reader(OLMo + projector, G-L1 자산)
  → 답 · 근거 위치 · 근거 날짜 · 판단 {유지 / 수정 / 보류}
```
- 학습: 질문·근거 정답(QA v0.1 확장: 근거 날짜·사분면·보류 라벨)으로 reader와 판단 모듈을 학습.
- 평가: 공간 상태 향상뿐 아니라 "과거 근거를 잊지 않고 새 관측에 적절히 반응하는 언어 판단"(판단 갱신 정확도, 보류의 적절성, 근거 인용 정확도)이 좋아졌는지.
- 순서: P1 v0 결과 → v0.1(9.1) → 사건 holdout(9.3) → reader 학습(9.4). VLM 부분은 교정기가 신호를 보인 뒤에만.

### 9.5 P1 v0 결과 (MS-135) — sanity 실패, 제안 교정기 음성
- 접두 arm 확인율 66%로 등록 sanity 미달 → 방법 해석 금지. 오경보 예산의 step 단위 면적 문턱이 과도할 가능성. v0.1에서 5%·10% 병행과 sealed 12창 참조 arm으로 readout 자체의 sanity를 분리.
- 기술적으로 resid_q(v0)는 Δt-GRU보다 20일 느리고 확인율 .55 vs .70. teacher-MSE 목표만으로는 조기 확인이 나오지 않는다는 §9.2 우려가 실측으로 확인됨. v1의 근거 기반 확인 목표 없이는 교정기 트랙을 계속하지 않음.
- 유지되는 사실: 확인율·IoU에서 GRU/Δt-GRU ≥ 전체 재인코딩(prefix), last는 빠르나 위치 품질 낮음.

### 9.6 P1 v0.1 결과 (MS-136)와 v0.2 계약
- sanity 미달 반복(5% 66%, 10% 89.7%). 원인은 step 단위 오경보 예산. v0.2: **타일 단위** 예산(사건 전 step 중 하나라도 문턱 초과면 그 타일이 오경보; 검증 타일의 5%/10%가 오경보가 되도록 문턱 설정).
- latest_head는 라벨 공간 누출로 무효(사건 전 관측에서 켜짐, FAR 1.0). v0.2: 같은 타일의 사건 전 step을 사후 step과 동일 가중 음성으로 두는 시간 대조 라벨, pos_weight 제거, 실현 FAR이 예산의 3배 이상이면 자동 무효 표시.
- sealed12는 타일당 1회 판정(연 전체 상태의 면적 ≥ 문턱)으로만 readout sanity에 씀. 지연 없음.
- 제안 교정기(teacher-MSE 학습)는 2/2 음성. v1(근거 기반 확인 목표)은 v0.2의 평가 계약이 sanity를 통과한 뒤에만 등록. 통과 못 하면 교정기 트랙 종료.

### 9.7 P1 v0.2 결과 (MS-137) — 계약 폐기와 방향 전환
- 봉인 readout + 면적 문턱 계약은 3회 sanity 실패로 폐기. 이유는 readout이 연 단위 정적 분할기라 도착 시점 변화 탐지에 맞지 않기 때문(sealed12 8~15%).
- 교정기(resid_q v0) 3/3 음성 → 트랙 종료. 방법 주장 없음.
- 새 사실: 시간 대조 라벨로 학습한 per-observation head는 첫 유효 사후 관측에서 91~95% 확인, 오경보 예산 내. 리뷰어 질문 "최신 영상만 읽으면 안 되나"에 대한 이 데이터의 잠정 답은 "head만 맞추면 된다"임.
- **v0.3(등록·실행)**: 모든 arm에 **같은 head 학습 레시피**(시간 대조, 동일 label·epoch)를 적용 — last/gru_dt/prefix/resid_q 상태 각각에 head를 학습해 확인율·지연·IoU 비교. gru_dt+head가 latest_head를 IoU·확인율에서 넘지 못하면 "이 과업에서 상태 기억은 위치 품질에도 기여하지 않는다"가 결론이고 T 방법 트랙은 종료. 넘으면 기억의 가치는 지연이 아니라 국지화에 있다는 것이 남는 주장.
- 어느 쪽이든 외부 사건 holdout(itogon·thrissur·hokkaido) 없이는 결과를 일반화하지 않음.

### 9.8 v0.3·사건 holdout 결과 (MS-139/140) — T 방법 트랙의 현재 상태
- 조기 확인 방법 후보 4종(학습 보간기, 품질·혁신 교정기, 단일 관측 시간대조 head, 기억 상태 head)이 모두 등록 관문 또는 사건 holdout에서 떨어짐. 단일 관측 head는 hiroshima 안에서만 성립(사건 특이).
- 살아남은 사실: (1) 사건 후 2관측 필요 곡선, (2) 강건성 경계, (3) 반복성 .85 수준·보간 +.03, (4) **한 사건 학습 head는 사건을 외우고, 교차지역 정적 readout은 전이하되 느림**, (5) 문턱 무관 사후 IoU에서 Δt-GRU 상태가 단일 관측보다 +.058(오경보 통제 없는 조건).
- 다음 실험(등록): **사건 단위 leave-one-event-out head** — 3사건으로 head를 학습하고 4번째 사건에서 평가(4폴드). 통과하면 "여러 사건을 보면 도착 시점 head가 일반화한다"가 되어 0일 확인 주장이 복구되고, 실패하면 도착 시점 탐지기는 봉인 readout으로 확정되고 VLM 트랙의 근거 입력도 그것으로 고정.
- VLM 트랙 귀결: 순차 QA v1 라벨은 마스크·메타에서 나오므로 유효. 근거 입력(사건 로그)은 hiroshima head가 아니라 LOEO head 또는 봉인 readout으로 다시 만들어야 함. 학습 사건 기억 대 규칙 로그 비교는 그 뒤.

### 9.9 LOEO 결과 (MS-141) — head 라인 종료, VLM 근거 탐지기 확정
- 4폴드 중 1폴드만 유효+70% → 규칙상 실패. 도착 시점 head는 사건을 여러 개 봐도 위치를 못 배우고(IoU ≤.10) 오경보가 사건 의존적. 라인 종료.
- 확정: VLM 비교의 근거 입력은 `event_log_v1`(각 지역 자기 LOCO 봉인 readout × 인과 접두 상태). 문턱은 지역별 사건 전 구간으로 재보정(MS-141 사실 2). 검증 블록 문턱과 hiroshima 이식 문턱을 둘 다 기록해 계약에서 명시 선택.
- 벤치마크 열 추가: "문턱 이식성"(사건 간 실현 FAR 산포). 조기 확인 방법 5종(보간기·교정기·단일 head·기억 head·LOEO head)의 등록 음성 결과는 논문의 negative-results 표로 보존.
- VLM 계약(`vlm_memory_comparison_prereg_v0_draft.json`) 잠금 해제 조건: 지역별 문턱 파일 확정, C/D 토큰 예산 동등성 명시. 이후 A(최신-only)·C(규칙 로그)를 먼저 돌려 "기억 무관" 판정을 조기에 받는 순서로 실행.

### 9.10 VLM 비교 stage 1 실행 (2026-09-19 저녁)
- 잠금 해제 조건 충족: 지역별 문턱(`event_log_v1/thresholds.json`, 자체 검증 블록 10% 예산) 확정, C/D 토큰 예산 동등성(로그 텍스트 ≤256 토큰 = 4슬롯×64) 계약에 명시. 평가 표본은 세트당 150타일×15 step(선언된 amendment_1).
- 실행: `vlm_memory_stage1_v0/` — arm A(최신 관측만) → C(최신 관측 + 규칙 사건 로그), projector-only, Olmo-3-7B frozen, 학습 7,590항목, 평가 4세트×2,250항목×4문항. GPU1.

- CAL_heuristic(텍스트 전용 달력 규칙, amendment_2) 바닥값 — hiroshima test / thrissur / itogon / hokkaido: Q_state .716/.660/.529/.575, Q_when .496/.444/.280/.354, Q_update .902/.858/.883/.855, cloud_stability .93 전 세트. Q_where .75~.78은 "none"이 맞는 비확인 step의 비율일 뿐(국지화 아님). arm A는 hiroshima 안에서 이 바닥을 Q_state +.18, Q_when +.41 넘으므로 순수 달력 암기는 아님. 미지 사건 판정은 이 바닥 대비로 읽음.
- stage 1 중간(arm A, 미지 2사건 완료): thrissur / itogon에서 CAL 바닥 대비 Q_state +.06/+.09, Q_when +.19/+.26 → EO 토큰이 사건 밖에서도 근거를 일부 읽음. 그러나 Q_update는 바닥과 동일(+.01)이고 **구름 안정성은 바닥 아래**(.850/.760 vs .926): 최신 관측만 읽는 VLM은 구름·무관 도착에서 답을 뒤집음. 판정 지표가 바로 이것이므로 "기억 무관" 분기는 구름 안정성에서 성립하기 어렵고, C(규칙 로그)가 안정성을 올리는지가 관건. hokkaido·C 대기.

- LOG_heuristic(모델 없이 event_log_v1를 지역 자체 10% 문턱으로 읽는 규칙, amendment_3) — hiroshima test / thrissur / itogon / hokkaido: Q_state .794/.758/.706/.859, Q_when .739/.752/.663/.781, 구름 안정성 0.980/0.985/0.997/0.976. 즉 **규칙만으로도 arm A보다 미지 3사건 Q_when이 +.12/+.12/+.05 높음**. - **stage 2 사전 판단(C 결과 읽기 전 기록):** LOG_heuristic 구름 안정성 .976~.997은 규칙이 첫 알림에서만 상태를 바꾸기 때문에 얻는 구조적 상한이고, Q_when .66~.78의 상한은 봉인 readout의 탐지 지연(MS-141: 0~77일)에 묶여 있음. 학습 사건 기억 D는 상태를 "읽을" 뿐 탐지 지연을 줄일 수 없으므로 Q_when에서 규칙을 크게 넘을 여지가 없고, 안정성은 이미 천장임. D의 남은 여지는 Q_where(규칙은 readout 사분면 그대로)와 잡음 관측에 대한 강건성뿐. 따라서 C가 LOG를 못 넘으면 stage 2는 "학습 기억이 규칙 로그를 이길 구조적 이유가 없다"로 보류하고, 벤치마크 논문(순차 근거 QA + 규칙 로그 기준선 + 음성 결과 표)으로 확정하는 것이 정직한 경로.

## 10. 신뢰도·보정 트랙 (2026-09-20, 사용자 6항목 중 실행 가능 5개 결합)
- 순서: 변화 점수 보정(MS-144, v0.1 진행) → 토큰별 신뢰 head(SCL 라벨) → 신뢰·z-점수 조건부 reader(stage 2와 같은 판정) → 신호가 나면 센서 정렬 post-training. 모델 크기 안내는 제외(사용자 지시).
- MS-144 핵심: 구름 쌍의 변화가 사건보다 큼(.351 vs .224, 정상 .121) → 신뢰 신호 없이는 보정도 reader도 구름에 흔들림. 정상 변화표는 지역 분산 체제가 맞을 때만 이식(hokkaido 실패).

- MS-146: 토큰 z는 사건 쌍 안 흔적 국지화 AUC .80(hiroshima LOEO .91). 순위 이식·문턱 불이식. reader 입력은 토큰 z 지도(연속값)+토큰 신뢰. 다음: 신뢰 head(SCL 토큰 라벨 4지역 완료) LOEO 학습 → 신뢰 마스킹이 구름 쌍의 z 오염(MS-144 .53~.82)을 줄이는지.
