# AI-Hub 신청 및 파생물 재배포 서면 문의 (2026-08-25 작성)

## 왜 서면 확인이 필요한가

논문에서 AI-Hub 데이터를 쓸 때 우리가 공개하려는 것은 **원본이 아니라 파생물**이다.
임베딩, per-tile 지표, 라벨 통계, 혼동행렬. 40 m 768-d 임베딩에서 원영상을 복원하는 것은
사실상 불가능하므로 근거는 강하다. **그러나 이것을 가정하지 않는다.** 서면으로 확인받는다.
확인 없이 공개하면 심사 중에 문제가 되고, 그때는 되돌릴 수 없다.

## 무엇을 신청하는가 — 선정 기준부터

**우리 실험에 AI-Hub의 영상은 필요 없다.** 필요한 것은 **라벨 + 좌표 + 촬영시점**이다.
Sentinel-2 12밴드는 rslearn으로 직접 materialize한다. 따라서 선정 기준은:

1. Sentinel-2 기반이어야 한다 (OlmoEarth의 native S2 modality와 맞아야 함)
2. 좌표계와 촬영시점(YYYYMMDD)이 있어야 한다 (STAC로 원 관측을 찾아야 함)
3. **같은 타일에 2개 이상 task로 나눌 수 있는 라벨**이어야 한다 (multi-task shared cache 실험)

### 신청 대상 (2026-08-25 포털 확인)

| 순위 | 데이터셋 | 번호 | 근거 |
|---|---|---|---|
| **1** | AI기반 국립공원 변화탐지 모니터링 플랫폼 구축 — **위성 10m급(Sentinel-2) 부분만** | **71363** | Sentinel-2 native, 3,000장, 9 클래스, EPSG:32652, 촬영시점 YYYYMMDD 포함, 폴리곤 좌표 |
| **2** | 토지피복지도 항공위성 이미지 | **71361** | Sentinel-2 900장(10m), 6 클래스, EPSG:5186, 2022 구축. 두 번째 한국 지역 = 지역 shift |
| 제외 | 지역안전재난(산불) | 71330 | **위성이 아니다.** 육상카메라 80% + 드론 20%, RGB JPG |

`aihubshell -mode l -datasetkey 71363`으로 filekey를 확인하면 10m 부분만 골라 받을 수 있다.
전체를 받지 않는다.

### 71363의 센서별 클래스 — 해상도 ladder가 아니다 (확인됨)

| 센서 | 클래스 수 | 목록 |
|---|---|---|
| 드론 0.1m | 10 | 건물·하천·주차장·도로·논·밭(하우스재배지)·해안쓰레기·산림·벌목지·비대상지 |
| 위성 0.5m Skysat | 8 | 건물·하천·도로·논·밭·산림·**산사태 및 토석류 피해지**·비대상지 |
| **위성 10m Sentinel-2** | **9** | 건물·하천·도로·논·밭·산림·**벌목지**·**산사태 및 토석류 피해지**·비대상지 |
| 위성 30m Landsat | 8 | 시가화건조지역·농업지역·산림지역·초지·습지·나지·수역·비대상지 |

ontology가 센서마다 다르고 **Landsat에는 산사태·벌목지 클래스가 없다.** 따라서 이것을
"같은 라벨의 4단 해상도 ladder"로 부를 수 없다. 10m Sentinel-2 부분만 쓴다.

### 10m 부분이 왜 multi-task가 되는가 (설계 가설 — 다운로드 후 검증 필요)

9 클래스를 같은 타일에서 성질이 다른 task로 분리할 수 있다.

```
task A  land-cover segmentation   건물·도로·논·밭·산림·하천 (다수 클래스, 넓게 분포)
task B  산사태·토석류 탐지         희소·이벤트성 (촬영시점이 있으므로 pre/post 구성 가능)
task C  벌목지 탐지               희소·인위적 변화
```

성질이 다르다는 것이 핵심이다 — 넓게 분포하는 다중클래스 분할 vs 희소한 이벤트 탐지.
task-specific risk가 갈릴 가능성이 높은 조합이다. **단 다운로드 후 확인해야 한다**:
세 task의 라벨이 실제로 같은 타일에서 겹치는지, 희소 클래스의 양이 학습에 충분한지.

## 사용자가 해야 하는 것 (내가 대신 할 수 없음)

| # | 항목 | 비고 |
|---|---|---|
| 1 | aihub.or.kr 회원가입 | 내국인 계정. 본인 인증 필요 |
| 2 | **71363**(1순위) 및 **71361**(2순위) 상세페이지에서 **다운로드 신청** → 승인 대기 | **API key와 별개다.** 키가 있어도 승인 없으면 다운로드 불가. 승인 리드타임이 전체 일정의 병목 |
| 3 | 오픈 API 안내 페이지에서 **API key 발급** | 등록 이메일로 수신 |
| 4 | 아래 문의서 발송 | 승인 신청과 동시에 보내면 대기시간이 겹친다 |

키를 받으면:

```bash
# 로컬 (저장소에 커밋되지 않는다)
cp .env.example .env && $EDITOR .env          # AIHUB_API_KEY 입력

# 서버 (키를 인자·히스토리에 남기지 않는다)
printf "AIHUB_API_KEY=%s\n" '<키>' > /home/work/data/olmoearth/.env.aihub
chmod 600 /home/work/data/olmoearth/.env.aihub
set -a; . /home/work/data/olmoearth/.env.aihub; set +a
bash code/aihub_setup.sh check
```

**키를 대화창·커밋·로그에 붙여넣지 않는다.** `code/aihub_setup.sh`는 키를 인자로 받지 않고
환경변수로만 읽는다 (프로세스 목록 노출 방지).

## 문의서 초안

> 제목: 학술 연구 목적 이용 및 파생 결과물 공개 범위 문의
>
> 안녕하십니까.
>
> 저는 위성영상 기반 지구관측 모델의 재현성을 연구하고 있으며, 연구 결과를 국제 학술대회에
> 논문으로 제출할 예정입니다. 귀 기관의 「AI기반 국립공원 변화탐지 모니터링 플랫폼 구축」 데이터셋
> (데이터셋 번호: 71363) 이용을 신청하였고, 학술 논문 게재 시 재현성 확보를 위해 공개해야 하는
> 항목의 허용 범위를 사전에 확인하고자 문의드립니다.
>
> 원본 영상 및 라벨 파일 자체를 재배포할 의사는 전혀 없습니다. 아래 세 항목에 대해서만
> 가능 여부를 서면으로 확인받고자 합니다.
>
> **1. 임베딩 등 비가역 파생 표현의 공개**
> 원본 영상을 딥러닝 모델에 입력하여 얻은 저차원 특징 벡터(임베딩)를 공개할 수 있습니까.
> 구체적으로는 지상 약 40 m 격자 단위의 768차원 실수 벡터이며, 이로부터 원본 영상을
> 복원하는 것은 기술적으로 불가능합니다. 원본 픽셀값이나 판독 가능한 영상은 포함되지 않습니다.
>
> **2. 파일 목록(manifest)의 공개**
> 연구에 사용한 정확한 부분집합을 제3자가 재현할 수 있도록, 사용한 파일의 이름과 파일별
> 해시값(SHA-256), 그리고 학습·검증·평가 분할 정의를 공개할 수 있습니까.
> 이는 파일의 내용을 포함하지 않으며, 동일 데이터셋 이용 승인을 받은 이용자만이
> 이를 통해 동일한 부분집합을 구성할 수 있습니다.
>
> **3. 국외 공동연구자와의 결과 공유 범위**
> 본 연구는 국외 기관 소속 연구자와 공동으로 수행될 수 있습니다. 이 경우
> (a) 원본 데이터에 접근하지 않고 (b) 위 1항의 파생 표현과 집계된 성능 지표
> (정확도, 혼동행렬, 클래스별 통계)만을 공유하는 것이 이용 조건에 부합합니까.
> 국외 연구자가 원본 데이터를 필요로 하는 경우 별도의 절차가 있는지도 함께 안내 부탁드립니다.
>
> 위 세 항목 중 허용되지 않는 것이 있다면 해당 항목을 논문에서 제외하고 진행하겠습니다.
> 회신 내용을 논문의 데이터 이용 조건 항목에 인용하고자 하니, 가능하다면 서면(이메일)으로
> 회신해 주시면 감사하겠습니다.
>
> 감사합니다.

발송 전 채울 것: 데이터셋 번호(승인 신청 시 확인), 소속·연락처.
